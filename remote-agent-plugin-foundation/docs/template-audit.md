# 模板公共能力检查

目标：复制后可以独立安装依赖、启动 Web/Server、登录、调用 API/MCP、查看结果和生成宿主配置。默认栈保持一套，不新增服务、依赖注入框架或自动模板升级系统。

| 能力         | 当前提供                                                    | 最小边界                                             |
| ------------ | ----------------------------------------------------------- | ---------------------------------------------------- |
| 配置与初始化 | 配置校验、随机密钥、私有 .env、不覆盖已有密钥               | 产品名称、权限、平台注册关系由 plugin.config.ts 声明 |
| 项目复制     | 独立源码、锁文件、全新密钥、清除平台关联                    | 不复制数据库、依赖、Git、历史凭据和交付物            |
| 账号与认证   | 邮箱密码、网站会话、设备码                                  | 未接入邮件验证与找回密码                             |
| OAuth        | 发现、DCR、PKCE、scope/resource 校验、续期                  | 试用允许公开 DCR；生产需单独确定策略                 |
| 授权连接     | OAuth 列表、按用户撤销、即时拒绝 MCP 访问                   | 不是物理设备统计；旧 CLI 尚不在连接列表              |
| HTTP         | 授权、同源写入检查、大小限制、安全头、可定位错误            | 没有通用业务权限引擎，资源归属由业务实现             |
| MCP          | 官方 SDK、HTTP/stdio 路径、按请求身份隔离                   | 工具定义和业务处理由 src/mcp 提供                    |
| API 客户端   | 固定源、超时、取消、禁止跨源跳转、不重试写入                | 业务响应校验属于业务客户端                           |
| 凭据         | 私有文件、按插件/来源隔离、退出清理                         | 不声称使用系统钥匙串                                 |
| 存储         | SQLite WAL、等待锁、事务迁移、重复执行与修改历史校验        | 单实例；不提供生产备份和多副本                       |
| 公共 Web     | 登录、设备码确认、OAuth 同意、连接管理                      | 简单 DOM 插槽契约，业务页面自主实现                  |
| 可观测性     | 请求 ID、脱敏错误、请求耗时和结果日志、health               | 未引入指标平台与分布式追踪                           |
| 构建与退出   | 静态资源随构建交付、停止接受请求后关闭数据库                | 容器文件已同步，Docker 执行未实测                    |
| 宿主包       | 一份 Skill、独立模板、生成标准根目录文件                    | 非 Codex 宿主尚未实机验收或完成提审                  |
| 测试         | 授权隔离、错误路径、MCP、迁移恢复、打包边界、公共层依赖方向 | 不依赖真实外部账号                                   |

## 本次补齐

- 将基础代码从产品代码中分离，公共模块不再导入笔记实现。
- 将笔记表、Schema、规则、HTTP 和 MCP 业务留在 src；只维护一份 Skill。
- 加入初始化、独立复制、静态资源构建和宿主配置生成。
- 加入事务迁移和改写历史检测；原有 notes 表可通过首次 IF NOT EXISTS 迁移接管。
- 根配置、Docker 构建入口和生成包目录一并更新。

## 不在本版增加

支付、组织权限、任务调度、事件总线、对象存储、邮件服务、自动运维、后台管理框架和多语言模板。真实业务需要时再接入现有成熟组件。

## 模板维护

复制后的项目可以独立修改 foundation；不依赖原模板的路径、账号和服务。模板后续修复通过说明和差异迁移，不自动同步或覆盖业务项目。宿主能力变化需要重新核对文档并实机验证。

## 验证记录

- 原项目与独立复制项目均通过 11 项测试、类型检查、格式检查和构建。
- 独立复制项目使用自己的 node_modules、随机 AUTH_SECRET 和空数据库；平台注册 appId 为空。
- 在 127.0.0.1:8792 启动复制项目的编译产物，浏览器完成注册、创建笔记并显示结果。
- 四种宿主的配置生成命令均执行成功；仅表示生成成功，不替代 WorkBuddy、豆包与 DSH 实机验证。
