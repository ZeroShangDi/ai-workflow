## 用途

### P1. 外部事件先验明正身

**问题**：处理外部系统事件（hook / webhook / 消息通知）时，事件可能对应不存在的实体，或重复、乱序。

**做法**：处理前先做身份/来源校验（"这个实体是我派发的 / 我见过的吗"）；**未跟踪实体降级为观测**——记日志但不落状态、不产生副作用；处理逻辑保持幂等（重复事件无害）。

**场景**：Claude Code hooks、后台代理生命周期事件、任何不可信来源的异步回调。

**反例**：`SubagentStop` 未校验是否见过对应 `SubagentStart` 就落账 → 幽灵事件（无 `agent_type`、无 transcript）生成假失败记录、触发补发到不存在的对象。

### P2. 重试循环必须有"无害出口"

**问题**：重试/补发逻辑只靠"次数上限"兜底，遇到永远失败（或其实已成功）的情况，会反复骚扰直到撞上限。

**做法**：重试入口先做**错误分类**——可恢复 / 良性 / 永久。可恢复才重试；**良性（已成功、重复、状态不可读）静默跳过，不产生副作用、不计数**。终止条件内置在分类里，而不是靠次数上限硬兜。

**场景**：落账失败补发、任务重试、指数退避、消息确认。

**反例**：`already done`（phantom 先落账 / 重复 Stop，本质是"已经成功"）被当可恢复失败写失败记录 → 补发 → 再撞守卫 → 循环到 `RESEND_MAX`。

### P3. 游标增量三件套

**问题**：增量处理日志/队列时，游标从 0 初始化 + 类型不一致的比较，导致历史记录整段重放或漏处理。

**做法**：① **初始化扫存量定起点**（不假设日志一开始为空）；② **时间戳归一化到同一单位**（毫秒）；③ **比较用同一类型**（不要 ISO 字符串 `<=` 数字）。配套补"第二次运行"测试。

**场景**：事件日志、驱动型日志、同步游标、消息偏移。

**反例**：`lastFailedTs = 0` + `rec.ts <= lastFailedTs`（字符串 `<=` 数字在 JS 中恒为 false）→ 昨天的失败记录每次 run 整段重放。

### P4. 契约单一事实源 + 测试锁定

**问题**：协议枚举/常量在多处各写各的（协议文档一份、实现白名单一份），必然漂移。

**做法**：枚举定义收敛到一处；**跨文件共识至少用一条测试断言"实现接受协议允许的全部值"**。

**场景**：RESULT status 白名单、事件名、配置键、错误码。

**反例**：`awf-worker.md` 协议写 `done|blocked|failed`，server 只收 `done|blocked` → 子 Agent 按协议输出 `fail` 被拒。

### P5. 集成边界补边界测试

**问题**：happy path 测试保护不了集成点；真实跨进程系统的事件会乱序、重复、带残留。

**做法**：对集成边界补**重复事件、乱序、残留输入、协议外输入**的测试；不能只测"第一次、正确、干净"的执行。

**场景**：跨进程 hook、网络回调、多 run 连续执行（第二次 run 读到上次残留）。

**反例**：落账链路集成测试只覆盖落账成功 → 幽灵 Stop、already-done、残留日志三个边界 bug 全部漏网。

### P6. 驱动型日志可清可初始化

**问题**：append-only 日志一旦反过来**驱动行为**（补发/重试/挂起），跨 run 累积就是污染状态——新 run 会把历史记录当成当前输入。

**做法**：驱动型日志 **per-run 清理** + 消费侧**防御性游标初始化**（双保险，一处失效另一处兜住）。

**场景**：`subagent-failed.jsonl`、`subagent-needs-input.jsonl`、任何被 CLI/消费者重读的追加日志。

**反例**：失败/决策日志跨 run 不清、游标不初始化 → 历史记录整段重放（与 P3 同源）。
