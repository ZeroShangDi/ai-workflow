## 2. 建议架构：两项全局服务，项目级会话和数据

```text
用户：CLI / DSH 网页中的 AWF 页面
             │
             ├─ CLI → AWF 全局 server
             └─ 网页 → DSH 插件提供的受鉴权入口
                                  │
AWF 全局 server                   │ DSH 全局 web 后台
  项目 A 的编排与状态   ←桥接→       薄插件：运行时调用、事件转换、UI 请求转发
  项目 B 的编排与状态               项目 A：规划 / 执行 / 子 Agent 会话
  每项目按配置装配 adapter          项目 B：规划 / 执行 / 子 Agent 会话
           │                                │
      .awf 任务与决策记录               DSH 原生对话存储
```

**AWF 决定做什么、何时做、是否通过门禁。适配器让不同平台以一致的业务含义完成动作；DSH 插件执行平台操作，不再拥有一套调度器。**

### 职责边界建议

| 部分 | 应负责 | 不应负责 |
|---|---|---|
| AWF 编排层 | 任务依赖、阶段链、配额、冲突、暂停、决策规则、门禁修复、动态规划 | tmux 按键、DSH 事件名、平台输出编码 |
| 平台适配层 | 创建/找到会话、执行与打断、平台事件归一、权限能力、数据读取、入口定位 | 决定下一个任务、擅自重试业务任务、判定门禁通过 |
| DSH 插件 | 在同一运行时驱动会话，按项目回传，承载 AWF 网页入口 | 跨项目默认回退、直接根据模型文本任意改任务状态 |
| 状态与存储层 | 延续现有 store 与锁约束，记录任务、决策、执行归属 | 把 DSH 原生对话完整复制成第二份主存储 |
| CLI / 网页 | 发起动作、展示结果、接受用户操作 | 各实现一套恢复和调度规则 |

### 全局单实例下必须明确的边界

1. DSH 插件代码在全局 profile 安装一次；项目启用关系、MCP 上下文和会话归属按项目配置。安装一次不等于向所有普通 DSH 会话注入 AWF 能力。
2. 每个项目分别拥有规划/执行会话绑定；全局运行时共享不等于共享一个对话。建议正常 run 新建执行会话，以已落盘计划为输入；`run -r` 才尝试复用执行现场。
3. 不将某项目的 `AWF_PROJECT_ROOT` 放在共享全局配置里代表所有项目。建议插件按会话作用域挂载该项目的 MCP，具体机制须验证。
4. AWF server 是已有的全局服务，DSH web 是另一项全局服务；不是合并成同一进程。停止项目只停止该项目执行，不顺带关 DSH。
5. 建议 `awf server stop` 继续只控制 AWF server；不静默扩大为“关闭整个 DSH”。任务结束后是否回收 DSH 由清单 U12 确认；两个服务的空闲与退出行为要分别定义，桥接心跳不能掩盖实际无人使用。
6. 后台运行不依赖浏览器标签页一直开着。关闭页面与进程退出分别验证，不能沿用旧 spec 的等同表述。
7. 人工直接在执行会话输入可能与 AWF 派发竞争。建议先进入人工介入状态再接受输入，待清单 U14 确认、X9 验证，不假定原生页面已遵守 AWF 的暂停规则。
8. 打断当前回答与停止整个 run 的对象范围分别定义，见清单 U11。当前 CC /stop 与 DSH cancel 都不能单凭一次调用证明子 Agent 和待执行队列全部停止。

### 建议的最小通信方案

沿用已定 WS：AWF→插件使用独立 WS 指令下行；插件→AWF 的确认、状态和结果暂建议用 HTTP POST，复用现有上报模式。现有 `ws.cjs` 不支持业务数据上行，不能当成完整双向通信库使用。

指令与观察事件分开：运行日志可重放，执行指令不能因订阅重连被自动重放。每条命令能关联项目、目标会话及一次执行，返回区分“已交给平台”“未交给平台”“无法确认”。CC 只能证实 tmux 注入时，不冒充已获模型受理回执。

连接中断时，先阻止新增派发并显示失联；连接恢复不自动等于任务恢复。无法核实执行结果时保留现场，沿显式恢复入口处理。**不承诺全套 exactly-once 或无损进程故障恢复。** 最小归属/指令记录用于防止误执行，不能为了免做记录而把未知结果当成功。

网页建议通过 DSH 插件的受鉴权入口请求 AWF；不在浏览器复制 DSH cookie 签名逻辑，也不把跨源直连 AWF 当成默认已可用路径。插件与 AWF 的连接也须绑定实例和版本；具体握手及字段由 AI 实现验证。

## 3. 能力全景：先确认打平什么，再确定接口名字

**“适配器统一”**指上层可以用同一种能力，不需要知道当前是 CC 还是 DSH；不要求底层机制、界面和原始数据完全一样。

下面 37 项是本轮盘点的能力，不等于 37 个端口。边界列为 AI 建议，等待用户审阅。证据编号见附录；DSH 未验证的部分保留条件，不因表中列出而视为已可用。

| ID | 能力与用途 | CC 当前情况 / DSH 目标或缺口 | 建议在哪一层打平及原因 |
|---|---|---|---|

| C29 | 发布命令、技能、worker 与决策资产 | CC 插件目录、命名空间；DSH 技能/命令加载不同 [S7,D3] | 业务资产尽量单源，适配器负责平台描述与挂载；不维护两套独立业务正文 |

### 新增 DS 能力树的边界核对

- 产品能力可以合并展示，但“打开页面”“启动后台”“创建会话”“停止会话”仍需分别定义语义。否则关标签页会被误写成停后台，已定全局单实例也无法正确管理。本稿保留这些细项供验收，不要求每项成为独立端口。
- 会话名、派发参数、输出解析是能力的数据或内部规则，不单独增加产品能力或 workers 端口。C18/C19 描述的是“派发真正发生、结果正确归属”这两个可观察效果。
- D-12 回调点已定：建议将 CC hooks 与 DSH 插件回调归一为共同事件/可返回动作；普通观测事件和需阻塞的回调要区分。平台状态快照用于初始连接与核对，事件用于持续更新，两者共同维护公共会话状态；决策等待由 AWF 维护，不直接等于平台 busy/idle。这是对 A10 的设计建议，待清单 U10 审阅；不强迫在“全靠回调”和“全靠读数”之间二选一。
- A9 管理方式建议采纳“面 / 能力 / 机制”的区分：已定方法、参数值与回调能力都有登记和实际消费者；必须能力缺失即失败，可选能力显式不支持。CI 检查登记与接线，行为测试验证语义。少量稳定端口是方向，数量上限不能代替职责合理性。此建议独立纳入清单 U9 审阅，不由 U1/U6 的整体选择代替。
- A8 两处 MCP 回退已查实：oneshot 可直连 CC 模块或启动 claude；snapshot 失败可回退 tmux。建议共享 MCP 经项目明确的 AWF API 取能力；如需保留 CC 离线能力，放回 CC 适配内部，DSH 禁止落入 CC 回退。monitor agent 中的平台描述改为单源模板加平台参数，不能不顾兼容性一删了之。

### 统一能力不等于统一所有细节

建议按“准备与安装、会话生命周期、会话控制与观测、平台事件/worker、隔离调用、界面入口”分组组织能力，映射到已定 host/session 方法及其他端口；遵守 A4 不新增 workers 端口。DS A9 的“三层登记”和 ≤8 目标仍未确认，不作为已定限制。

保留的平台差异包括：终端/网页交互、原生对话呈现、插件包格式、命令名字、工具名、可取得的用量精度。适配层需显式描述差异；上层不因一次任务需要这些能力而导入 CC/DSH 的具体模块。

本轮只做仓库及本机已安装包的静态核查，没有启动新的 DSH 服务、安装插件或消耗模型调用。历史 spike 标为“旧文档报告”，不会升级成“本轮实测通过”。

| 项 | 本轮证据与结论 | 仍需验证什么 |
|---|---|---|
| 版本 | 本机 launcher 0.1.5-rc.1；所查内部包 0.1.5-rc.2 [D1] | 作为验证基线固定版本；升级兼容另测，不能使用当前 dist-tag 的历史判断代替版本记录 |
| 内部取消 | controller 调用 agent.cancel，返回 accepted，且 keepInbox:true [D2] | 插件可调用性、实际终止信号、清队列、子 Agent 停止；旧文档 `{ok,error}` 不能直接当内部返回形状 |
| 提交回执 | controller prompt 使用 requestId 检查，并返回 accepted [D2] | 原生去重能覆盖哪些范围、并发和重启；不凭一段代码宣称持久化 exactly-once |
| 命令执行 | 内部 commands.execute 接收 agent、line、attachments、signal [D3] | 哪个公开运行时服务可调用、w-plan 如何加载；不照抄清单里的 sessionId 简化签名 |
| 子 Agent 输出 | 内部代码发 subagent/start、subagent/end；末条内容为块数组且某些失败路径不含输出 [D4] | 插件订阅作用域及 continuable 多轮顺序；SDK 的 subagent.finished 不能直接作内部事件名 |
| 工具限制 | tools.restrict 要求作用域；限制全局工具名，注释明确 scoped registrations remain visible [D4] | 项目 MCP 若按会话注册，worker 的写工具是否仍可见；必须实际调用被禁工具验证 |
| MCP 隔离 | MCP client 支持作用域归属，stdio 用显式 env/cwd [D5] | 单后台多项目装配、子 Agent 继承、命名冲突与卸载清理 |
| 技能 | filesystem 代码按 cwd 查根目录，并识别 SKILL.md [D3] | 36 项资产兼容、命令/技能发现与权限；不能把文件格式可读等同全部行为可用 |
| plugin 命令 | launcher 将剩余参数转交 profile 包管理 [D1] | list/remove 与 bundle 注销的实际行为，卸载是否影响其他项目 |
| batch 确认 | 当前代码看事件条数增加，不绑定当前任务 [S5] | DSH 共享运行时下需要精确关联；不得照搬“任何子 Agent 启动即本次派发成功” |
| 结果落账 | 当前 recorder 直接调用 store.updateSync [S5] | 原 spec“仍走 awf_task_complete”与当前路径不同，应统一公共落账语义再接入 |
| UI 与实时性 | 插件同运行时、slot 及刷新结论来自旧 spike | 本轮单后台多项目及新插件驱动下重新验证，不把架构选择本身当实时性验收 |

“worker 权限不降级”在这里指工具暴露与调用限制；现有 worker 仍获授 Bash/Edit/Write，不能把工具白名单宣称为操作系统级禁止写入 state 文件。若要增加文件系统强隔离，应单独列范围，不能在本轮承诺中暗含。

最关键的组合风险是 **项目 MCP 作用域与 worker 权限**：两个功能分别“存在”，不代表放在一起还能限制工具。P0 必须验证这一组合；用户已经确定不降级，因此失败时应报告约束冲突，不能自动启用弱限制。

## 5. 恢复方案：沿用入口，先修正对现状的理解

### 已查明的当前行为

- `run -r` 将环境准备设为复用现场，并保留 pause；但随后仍调用 submitRun，没有像 `--attach` 那样查询活跃 run 后只订阅。[S2]
- host 对已存在的活跃 run 拒绝再次提交；所以帮助文案“活跃 run 挂接续观”没有在这条 CLI 分支完整实现。[S8]
- host 的 run 记录和事件环是内存 Map/数组。server 重启后 `.awf/state.json` 仍在，但不能据此恢复原内存 run。[S8]
- 下一任务选择只取 pending。遗留 active 不会因 `-r` 自动变回 pending。[S8]

这是静态代码结论，不代表已经重现全部故障场景。用户提到“可能先手动重置状态”与代码缺口相容，但不能建议不分情形地把 active 全部重置，否则仍在执行的任务可能被重复派发。

### 建议本轮最小恢复行为（待审阅）

| 现场 | 用户操作与期望 | 本轮建议处理 |
|---|---|---|
| 仅 CLI 退出，AWF run 和 DSH 都在 | `run -r` 继续观察 | 修正 -r 的活跃挂接分支，不重复提交；CC/DSH 共用 |
| AWF 与插件联系丢失，但进程状态不明 | 显示故障，避免错误推进 | 暂停新增派发、保留证据；通道可尝试恢复，但不盲目重发或自动恢复业务 run |
| AWF server 重启，DSH 可能仍执行 | `run -r` 核查现场 | 根据执行归属及平台状态核对；只有确认可恢复才接入，否则明确指出未确认任务 |
| DSH 退出，AWF 仍在 | `run -r` 重新准备并核查 | 不永久显示 busy；已结束、未执行、执行未知分别处理 |
| 遗留 active 无法确认 | 需要人工处理后续跑 | 展示具体任务和最后证据，通过现有受控状态操作处理；不自动把所有 active 重置 |

本轮增加的最小持久信息建议仅包含项目/会话绑定、任务执行批次和待确认指令归属；不复制整套 DSH 历史，也不持久化整个 scheduler。具体字段、写入时机和清理策略由 AI 设计。

- CC 结构化对话页升级、统一观测数据库、整个 scheduler 重写、全面清理历史债务。

- 只因部署机制不同就放弃 plugin local/global、plan -r、run --attach 等既有操作；这些需要明确等价行为，不能用“七个命令有入口”代替支持。

**P0 新增的跨项事实（不属 X1～X9，但影响实现）**
