# AI 完全自主实现商业级项目的卡点

> 2026-08-16 · 讨论记录 · 回答"真正阻碍 AI 完全自主实现一个商业级项目的是什么"

## 结论

卡点不在执行，在「正确」没有被定义在系统内部。

当前 awf 的环是：AI 生成 spec → AI 执行 spec → AI 验收 spec。三个环节是同一个智能在动，环里没有第二个信号源。而"完全自主"= 把人类这个唯一的环外信号也拿掉。于是系统变成自指闭环 —— 它只能回答"我有没有建成我猜的东西"，永远回答不了"我猜的东西对不对"。

## 三道墙

### 1. 验收标准是天花板，而它是动手前猜的

acceptance 在 plan 阶段、一行代码没写之前就生成，是系统对"done"的唯一定义。但商业级项目里，错误的主要藏身处恰恰是 spec 本身 —— 需求理解偏、边界没想全、权衡押错。门禁/审查/测试全在问"符不符合 acceptance"，而 acceptance 可能是错的靶子。这种失败**静默且自信**：系统会成功地把错的东西做完，全程绿灯。

### 2. 只有 DEBUG 环，没有 re-plan 环

任务 DAG 在 plan 时冻结。DEBUG 处理"我的代码有 bug"，处理不了"任务 3 的设计在任务 40 被证明是错的"。商业项目的真实工作量绝大部分是后者 —— 边做边发现计划错了、回头改。系统给了执行和失败两个出口，没给"修订计划"的出口。

### 3. 隐性判断力写不进 skill

商业级和 demo 的分野 —— 架构口味、可维护性、何时该重构、安全上的直觉 —— 大半是 tacit 的，是"被真实系统烧过"沉淀的，不是"能写下来的规则"。skill 能编码专家知识，但天花板就是"能显式化的那一部分"。

## 收敛

"正确"的定义住在系统外部：用户意图 + 生产现实，两者都不在环里。再加固自审、记忆、checkpoint，都是在让自指环更自洽，加不出环外的东西。

要"完全自主 + 商业级"同时成立，必须把 oracle 放进环里。唯一能替代人类当 oracle 的，是**可执行的现实**：一个 AI 能跑进去、能观测后果的环境 —— 真实运行态、可执行的行为断言、真实或逼真的数据、生产遥测。

这不是 prompt 或 skill 层面能解决的，是"环境 + 反馈回路"层面。没有它，"完全自主"和"商业级"本质矛盾 —— 要后者，就得给前者一个现实来兜底。
