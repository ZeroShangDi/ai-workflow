# AI 主导全量重构的元实验复盘（v0.2.0）

> **复盘对象**：v0.2.0「全量一次性架构重构」—— 由 AI 在 `awf run` 编排下主导完成，人只做裁定。
> **格式**：Stable / Improve / Experiment（默认格式）+ 卡点 / 边界决策 / 验证结论三节留档。
> **素材**：`.awf/issues/001–004`、`docs/bugs/` 与 `.awf/bugs/` 共 9 条、`.awf/reports/`（test/review/perf/lint/summary）、
> `docs/discuss/planned-architecture-landing.md`、`docs/discuss/architecture-v0.2.0.md`、`docs/CHANGELOG.md`。
> **规模**：167 个 WBS 节点 / 153 个任务（145 done）· 8 个模块门禁 + 1 个模块门禁两次返工 + 1 个全量真机门禁 ·
> 87 个生产文件受结构门禁约束 · 36 份功能文档 + 1 份架构终稿 · 真机回归 13 case × 150 断言。

## 一、这次实验的设定（读结论前先知道）

- **实验组**：AI 主导。人只在「边界处」出现 —— 裁定跨代取舍（决策入口换代、互斥化暂缓）、拍板仓政策（锁文件）。
- **交付物是工具本身**（自举）：被重构的东西，正是让 AI 能持续工作的编排器。
- **验收面有三层**：单测/集成（`npm test`）→ 结构门禁（`check-architecture`）→ 真机回归（`test:real`）。
  本次复盘的重点不是「交付了什么」，而是**这三层验证各自在哪里骗过了我们**。

## 二、卡点（卡在哪、为什么、怎么出的）

| # | 卡点 | 现象 | 根因 | 出路 |
|---|---|---|---|---|
| **K1** | **抽象建了没接线** | 6 个重构产出的抽象模块（`run-registry` / `app` / `api` / `layout-migrate` / `persist-pipeline` / `session-launch`）零生产引用，却有 4 个被测试绿守护；`server.cjs` 仍是 1435 行单体（现 1491，结构断言上限 1600），会话启动真身仍是 `bootstrap.sh` | **「建抽象」与「接上 live」写在同一条任务里，而验收只判「建成」** —— 接线成了口头承诺。task result 里的「待 W3-003/004 接入」随着那些任务 done 变成永不接入 | `check-architecture` 不变量①：**生产侧零引用，测试 import 不算采用**；删除优于标注（`.awf/issues/002`） |
| **K2** | **验证面的假象** | 「重构已落地」在验证面成立（测试绿），但被验证的抽象从未被生产路径采用 | 覆盖 ≠ 接上；测试守护的是**实现存在**，不是**实现被用** | 判据从「有测试」换成「有生产引用」；`.awf/issues/002` |
| **K3** | **登记 ≠ 可达** | 豁免表 4 条结构债都写了 `responsible: T1-113`；而 T1-113 挂在**被用户明示暂缓**的 T1-106 之后 → 责任人永不可就绪 | 字段齐备被当成了登记完成；**没人验过「那个责任人走得到吗」** | `unreachableResponsibles()`：判据取自 `state.js:depsDone`（依赖闭包内有 blocked ⇒ 永不可就绪）+ 打真实任务图的单测 |
| **K4** | **自述失真** | 契约/注释/文档把**目标**写成了**现状**：`ports.cjs` 自称「外部源码零 claude 字面」而它自己反向 require server；`awf-oneshot/server.cjs` 写「claude 字面不在本 MCP」而同文件降级路径就是 `spawn('claude')`；harness 注释写「未构建回落 legacy 观测页」而实现早已改成 503；`CLAUDE.md` 同文件内自相矛盾（await 工具「在册」与「已停用」并存） | 「零导入」「已收口」这类话**写的时候是真的**，之后代码动了、话没动 | 铁律：**只写能取证的**（附命令输出或 `文件:行号`）；契约声明要能被断言钉住（「契约里的每个方法必须真实存在」） |
| **K5** | **沉默的失败** | 缺 `?p` 的写请求静默兜底到 boot 项目 → **一条手工 curl 把在跑的 run 暂停了 4 小时**；页面缺产物静默回落；前端**从未被构建过**却没有任何环节报错；缺依赖时构建静默跳过 | 兜底路径「看起来更友好」，实际是把错误藏起来 | 统一口径：**把沉默变成会响的东西** —— 写类缺 `?p` → 400、缺产物 → 503 + 告警、架构依赖缺失 → 报错并给修复命令 |
| **K6** | **单测拦不住真机故障** | `awf init` 因 ESM 具名导入从 `module.exports = {...展开}` 取值而直接挂；**单测全绿** | vitest 的 CJS 互操作 ≠ Node 原生 ESM-CJS 具名导出分析 —— 两个运行时，两套规则 | 真机 harness 抓出来后，把「ESM/CJS 具名导出必须顶层 const」写进代码注释；`check-arch`、`build`、真机三层互补 |
| **K7** | **观测者效应** | `lifecycle` case 首版把「轮询等 server 关闭」写进实现，而 server 每次请求都刷新 `lastActivityAt` —— **测试自己把它喂活了** | 把「观察」当成了「不干预」 | 探活与判定分离；该 case 改为探活段 + 静置段两段式 |
| **K8** | **验证工具自身也有缺陷** | 结构门禁的不变量①**漏检**：扫描正则把**注释里的 import 当真引用**（`src/lib/version.js` 两处调用点都被注释掉，门禁仍报「零引用：无」）；真机 harness 在全量连跑下自身 case 隔离不成立（5 项失败，单跑全绿） | 检测器的判据来自「文本长什么样」，而真相是「运行时发生什么」 | `.awf/issues/003`（→ `T1-120`）；真机 case 隔离性（→ `T3-011-F1`）；**新规矩：每个验证手段都要有元验证** |

**贯穿 K1–K8 的一条主线**：**我们反复把「登记/验证的形式成立」当成了「事实成立」**。
抽象建了 ⇒ 以为接上了；测试绿 ⇒ 以为落地了；写了责任人 ⇒ 以为有人做；契约写了 ⇒ 以为实现如此。
每一次都是**形式**先成立，**事实**后缺席，而且**缺席时不响**。

## 三、边界决策（这一版把线划在哪、为什么）

| 决策 | 线划在哪 | 为什么划在这 |
|---|---|---|
| **决策入口换代** | 停用「AskUserQuestion 上抛 → `/respond`」，改走 `<AWF_DECISION_REQUIRED>` 门阀（资产层停用，代码面保留待互斥化） | run 内需要决策时人不一定在场；上抛链路把「跑得下去」压在人在环上。互斥化本身**用户裁定暂缓** —— 边界是「先能自洽，再谈两代共存」 |
| **写类端点缺 `?p` → 400** | 唯一豁免 `/shutdown`；读类保留 boot 兜底 | 读的兜底是「CLI 找 server」的必要入口，写的兜底是隐患。**错误必须显式** |
| **删除优于标注** | 判据 = 生产侧零引用 **且** 能力已在 live 路径别处实现 | 留在树上的悬空骨架会被下一次读代码的人误当现状。`migrate.cjs` 连迁移能力都没有（`MIGRATIONS = []`），删除不损失能力 |
| **门禁可失败化** | `check-architecture` 进 `npm run build`，有未豁免违例即中断 | 「机器能拦住的，就不该只写在提醒里」。同时**不放宽判据**换绿 —— 存量债进 `EXEMPTIONS` 并指责任务 |
| **未收口必须结构化登记** | `ports.cjs` 的 `status: 'factory' | 'not-landed'`（缺 `note`/`responsible` 加载即抛）；`EXEMPTIONS` 每条 reason + responsible | 「沉默的 `false`」等于没有登记；未收口要么现在做，要么变成一条**会响的**待办 |
| **真机回归分两种粒度** | 全量 `--case all`（最终验收）+ 定向 `--case <name>`（开发期快反馈） | 上一版的教训是「门禁只在收尾跑一次 → 问题积到收尾才炸」 |
| **锁文件入库** | `web/package-lock.json` 入库，与根锁同规矩 | 拒绝入库的唯一理由是镜像 URL 绑定，而根锁**本来就是** npmmirror 且已入库 —— 收益为零、可复现性为负 |
| **文档只写能取证的** | 功能文档必须给 `文件:行号`；自述与实现不符按缺陷处理，不按文字问题处理 | K4 的反复教训 |

**一条被反复确认的元边界**：**AI 可以自决「怎么做」，但「要什么」的边界必须由人划**。
本次可核到的人工裁定只有四条，且全部是**产品取向**而非工程判断：
① 2026-09-10 决策入口统一走自动决策（新代门阀）；② 2026-09-10 两条决策链互斥化**暂缓**；
③ 2026-09-10 `awf plan` 全链路**暂不测**；④ 2026-09-11 A/D 不是新里程碑、仍属 v0.2.0。
**反例同样有信息量**：`web/package-lock.json` 的去留最初被 `T1-118` 以「要不要入库由你定」上抛给人，
最终却由**决策门阀自决**（依据：根锁本就入库且同为 npmmirror）—— 这类「仓政策」问题本就不该占用人。

## 四、验证结论（凭什么说它成了）

### 4.1 机器证据（可复现）

| 手段 | 结果 | 说明 |
|---|---|---|
| `npm test` | **95 文件 / 852 例全绿** | 单测 + 集成 + e2e |
| `npm run lint` / `npm run build` | 通过 | build 串了 render-config → 语法 → **结构门禁** → web 构建 → `npm pack --dry-run` |
| `scripts/check-architecture.mjs` | **EXIT 0**：零生产引用 **0**、依赖方向越界 4（全部登记且责任可达） | `--strict` EXIT 1 属预期（4 条结构债未清） |
| 真机 `npm run test:real` | 13 case / **146–150 断言**，产品路径**零回归**；5 项失败全部归因 case 侧 | 见 `.awf/reports/test/t3-011-full-real-gate.md` |
| 文档一致性 | 36 份功能文档全仓引用扫描**零失效**；渲染幂等（重跑 `render-config` 零 diff）；版本六处对齐 0.2.0 | — |

### 4.2 结论

- **成立**：编排链路的**行为不变**（单/多 agent、决策闸门、门禁闭环、双 run 隔离、重连、pause 闩锁与放行、中断恢复）在真机跑通；
  结构债**有主且可达**；失效模式（K1/K2）**已由机器持续拦住**，不再依赖人记得。
- **不宣称**：`--case all` 全绿 ≠ 功能全绿（覆盖矩阵 `docs/discuss/real-run-coverage-gaps.md` 是边界声明）；
  R2（隔离）/R3（事件版本）无机器守卫；`--strict` 未通过（4 条结构债在册）。

### 4.3 这次实验真正答对的一件事

**把「教训」变成了「判据」。** 上一轮踩过的坑没有停在复盘里：
「抽象没人用」→ 门禁不变量①；「责任写没人验」→ 责任可达性断言；「沉默的失败」→ 400/503/构建报错；
「自述失真」→ 只写能取证的 + 契约方法存在性断言。**一条教训对应一条会失败的检查**，这是本次最值得复制的东西。

## 五、Stable / Improve / Experiment

### Stable（保持，≤3）

1. **三层验证互补**（单测 → 结构门禁 → 真机）：三层抓到的是**不同类**的问题 —— 单测抓逻辑、门禁抓接线、真机抓运行时；
   K6（ESM 具名导出）只有真机能抓，K1（零引用）只有门禁能抓，缺一层就漏一类。
2. **门禁只判不改，修复派生独立任务**：判与修分开，使「判」保持可复现，也让修复带上责任与轮次上限（`MAX_RECHECK=3`）。
3. **把裁定权留在人、把执行权放给 AI**：人只在**产品取向**上出现四次（见 §三 末），工程判断全部自决 —— 这个分工使 153 个任务里没有一次「等批示」造成的停滞；连「仓政策」这类本不该占用人时间的问题，也由决策门阀自决掉了。

### Improve（改进，≤3）

1. **验证器自身没有元验证**：K8 两条（门禁假阴性、harness 自身不隔离）都是「验证工具骗了我们」。
   现状是所有断言都在验产品，**没有一条在验「验证器本身会不会撒谎」**。
2. **结账口径不统一**：同一批失败里，「产品缺陷 / 测试缺陷 / 环境缺陷」的区分全靠执行者临场判断（T3-011 靠单跑 vs 连跑对照实验才分开）。
   这应是**流程标配**而不是个人手艺。
3. **任务粒度的「接线」维度缺失**：K1 的根因是任务拆分时没有「接线」这一刀 —— 直到 `planned-architecture-landing.md` 才显式补上「抽象任务与接线任务一一对应」。

### Experiment（尝试，≤3）

1. **给每个验证手段配一条「负面用例」**：新加一条断言时，同时加一条「故意让它该红」的用例（如：只有注释引用的模块必须被判零引用）。
2. **门禁失败先做对照实验**：断言失败时，同一 case 单独跑一次 —— 单跑绿而连跑红 ⇒ 隔离性问题，先修 harness 再谈产品。
3. **收尾前跑一次「反向自检」**：不查「哪里不对」，而查「我凭什么说它对」—— 逐个台账（豁免表 / issues / 文档自述）问「这条现在还是真的吗」。
