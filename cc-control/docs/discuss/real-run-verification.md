# 全真测试的定位与失败自愈（记录）

> 2026-09-10 · 状态：**方向记录，尚未排期**。触发：T1-098 真 run 失败后必须人工介入 + 大量改动。

## 背景问题

真 run 一失败就"死机"：`awf run` 走「保留现场退出、等人 / 等 w-monitor」，没有自动定位、
没有自动修复、没有自动重跑。用户判断：**正常场景下全真测试失败不该必须人工介入**。

## 用户裁定的两点核心

1. **全真测试只在开发完全结束后做验收**，不要散在任务图中间。
   （本次项目里只留了 T1-098 一个全真任务，就是为了避免浪费 —— 每次全真都真起 tmux + 真 claude。）
2. **全真失败必须能自动定位问题、修复、再运行**，而不是停下等人。

## 现状与缺口

| | 现状 |
|---|---|
| 通用失败处理 | 「保留现场退出，供 w-monitor 诊断」→ 人工 |
| 门禁类任务（`kind: review/test`） | **已有**自动闭环：blocked + verdict 非 pass → 派生修复任务 + 门禁回退 pending 重跑（`gate-fix.js`） |
| 全真回归任务（`kind: dev`，如 T1-098） | **接不上**闭环 → 失败只标 blocked，run 结束 |

→ 缺口根因之一：**全真回归是 dev 类任务，没进门禁闭环**。把它做成门禁类（产出结构化
verdict + 证据）即可复用现成的「失败 → 派生修复 → 重跑」。

## 特殊性与一般性

本次死机还有一层特殊性：**被测对象就是编排器自己**（宿主执行器 / hook 形状 / settle 判据），
出 bug 的地方正是负责"自我恢复"的机器，所以连兜底也一起坏了。换成测业务功能（编排器健康、
被测的是被编排的项目）时，门禁闭环是能兜住的。

## 已解除的历史约束

当初"不能中途插全真"是因为**嵌套 run 会互杀**（kill-by-port / kill-session）。单 server 多项目
（?p 路由 + 每项目 tmux 会话名 + 项目上下文隔离）落地后，**run 内部已经可以起沙箱真 run** ——
`tests/regression/fullflow-regression.mjs` 的 `dual` case 就是 run 会话内发起的，15/15 通过。

即：**"只在最后做全真" 不再是硬约束，可以在中途插入低成本的全真烟雾（沙箱项目）。**

## 配套

失败自动定位 / 自愈**与「动态任务规划」能力配套上线**（用户裁定），不单独做。
