# 提示词 vs Skill vs 知识库

## 一句话区分

| | 本质 | 类比 |
|---|---|---|
| 提示词 | **这一次**我要求你怎么做 | 口头交代 |
| Skill | **每次这类场景**你都要怎么做 | SOP 手册 |
| 知识库 | **你需要知道的**事实和背景 | 档案柜 |

---

## 判断矩阵

同一个内容 "一次只解决一个问题" 放在三者里，效果完全不同：

| 形态 | 生效方式 | 什么时候用 |
|------|----------|-----------|
| 提示词 | 只对当前对话生效，说完就完 | 你发现 AI 这次在跳跃，临时纠正 |
| Skill 规则 | 每次触发该 skill 时自动加载 | 你希望 AI 在任何调试场景下都遵循这个原则 |
| 知识库 | AI 需要时查询，不主动生效 | 你希望 AI 在做决策时能参考这个方法论，但不强制 |

---

## 决策流程

遇到一段内容，按这个顺序问自己：

```
这段内容要固化吗？
├── 不固化，就这次用
│   → 提示词。发完就完了。
│
└── 要固化，以后也要用
    │
    ├── 它是「怎么做」的规则吗？
    │   ├── 总是适用（如代码风格）
    │   │   → 放进 CLAUDE.md 或 always 类型的 skill
    │   │
    │   └── 特定场景适用（如调试时、提交时、审查时）
    │       → 放进对应的 skill，由该场景自动触发
    │
    ├── 它是「是什么」的事实吗？
    │   ├── 需要 AI 做决策时参考
    │   │   → 知识库
    │   │
    │   └── 项目级别的约定（如分支命名、目录结构）
    │       → CLAUDE.md 或项目 skill
    │
    └── 它是「为什么」的背景吗？
        → 知识库。让 AI 理解决策背后的原因。
```

---

## 具体场景判断

### 放提示词里

- 这次对话的临时约束："这次只改这一个文件"
- 阶段切换信号："方案没问题，开始写代码"
- 即时纠正："方向不对，换一个思路"
- 想知道 AI 当前理解："先复述一遍我的需求"

**特征**：有效期只有这次对话，对话结束就失效。

### 放 Skill 里

- 反复执行的流程：DEV→REVIEW→TEST→COMMIT 的阶段链
- 写代码时的规则：命名规范、错误处理方式、禁止事项
- 代码审查的维度：正确性、边界、耦合、性能
- 提交时的约束：中文 message、不要 push、不要署名

**特征**：每次遇到这个场景你都不想再说一遍。

判断标准：**如果同样的规则你在三次以上对话中都说过，就该进 skill 了。**

### 放知识库里

- 历史决策和原因："为什么选了 A 方案而不是 B"
- 踩过的坑："浏览器翻译插件会导致 DOM 变化引发下标错乱"
- 架构背景："这个模块拆成了三个 MCP server，各自负责什么"
- 外部信息："Figma MCP 是怎么安装的"
- 方法论："渐进式纠偏三段法"、"链式排查法"

**特征**：AI 不需要每次都知道，但需要时能找到。

判断标准：**如果你希望 AI 在做决策时能"想起来"这件事，放知识库。**

## 一个内容的三种形态

以"一次只解决一个问题"为例：

| 形态 | 写法 | 什么时候用 |
|------|------|-----------|
| **提示词** | `我们一个一个问题解决` | 这次对话中 AI 在跳跃，临时纠正 |
| **Skill 规则** | `解决问题时，一次聚焦一个问题。解决完并确认后，再进入下一个。禁止同时处理多个不相关的问题。` | 写进 debug skill，每次调试自动加载 |
| **知识库** | `方法论：增量问题解决法。将复杂问题拆解为独立的小问题，逐个定位和修复。| 为什么：同时处理多个问题会引入干扰变量，无法确定是哪个修复生效。| 如何执行：1.列出所有可能原因 2.按可能性排序 3.从最可能开始逐个排除 4.每排除一个记录结果` | AI 做排查策略决策时可以参考 |

## 固化路径

你日常使用的自然路径：

```
第 1 次：发送提示词 → 发现有效
第 2 次：复制粘贴同样的提示词 → 又有效
第 3 次：意识到这会反复用 → 判断属于哪个场景 → 写进对应 skill
第 N 次：skill 积累了足够多的规则 → 抽出通用的方法论部分 → 放进知识库
```

**核心原则**：先用提示词验证有效性，确认有效再固化。不要一上来就建 skill 和知识库。

## 速查表

| 我想让 AI... | 用什么 | 放哪里 |
|-------------|--------|-------|
| 这次对话按这个方式工作 | 提示词 | 对话框里直接发 |
| 每次写代码都遵循这个规范 | Skill | code-standards skill |
| 每次提交都加上这个约束 | Skill | w-commit skill |
| 以后做类似决策时参考这个原因 | 知识库 | memory / docs |
| 知道项目的历史背景和架构 | 知识库 | CLAUDE.md / docs |
| 了解我踩过哪些坑 | 知识库 | memory / docs |
| 执行一个多步骤的工作流 | Skill | 对应 slash command |
| 这次临时改个方向 | 提示词 | 对话框里直接发 |
