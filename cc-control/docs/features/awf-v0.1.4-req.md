# v0.1.4 需求文档 — 任务层级体系重构

> 来源讨论：`docs/discuss/task-hierarchy-redesign.md`
> 状态：active
> 版本：v0.1.4

## 背景

当前 `flow-rule-task` 定义的任务层级链条将时空维度混排：

```
生态级 → 系统级 → 里程碑级 → 项目级 → 模块/需求级 → 功能级 → 任务级 → (动作级) → (原子级)
```

里程碑级和需求级属于时间维度，其余属于空间维度。混排造成理解和使用混乱，需要分离。

## 需求

### R1: 时空双轴分离

- **空间轴**：T1-T9 层级，描述系统架构的物理分解（一棵会进化的树）
- **时间轴**：里程碑 → 需求，描述版本推进的线性追加（一个不断 append 的数组）
- 任务通过 `space` path 和 `time` path 锚定到两个轴的交叉点

### R2: T1-T9 空间层级定义

| 标识 | 层级 | 说明 |
|------|------|------|
| T9 | 生态级 | 多产品多项目商业版图 |
| T8 | 系统级 | 多项目共同实现一个目标 |
| T7 | 项目级 | 一个完整可部署的单元 |
| T6 | 模块级 | 自包含的子系统 |
| T5 | 功能级 | 用户可感知的能力 |
| T4 | 任务级 | 一次会话能解决（最小使用单位） |
| T3 | 动作级 | 不独立存在 |
| T2 | 原子级 | 不独立存在 |
| T1 | — | 预留 |

- 叶子可停在任意层级（小功能到 T5 即停，不强制拆到 T4）
- T1-T3 只存在于概念中

### R3: DFS 后序遍历生成任务清单

- 遍历空间树，深度优先后序
- `done` / `skip` 状态的子树跳过
- T4+ 叶子节点 → 生成可执行任务
- T5+ 非叶子节点 → 子节点全部完成后触发门禁

### R4: 门禁配置化

- T5+ 每层配置对应门禁（测试 + 审查）
- 时间轴配置需求级门禁和里程碑门禁
- 统一存储在 `.awf/gates.yaml`，支持项目级覆盖

### R5: 空间树更新时机

| 事件 | 更新空间轴 | 更新时间轴 |
|------|-----------|-----------|
| 首次 init/plan | 生成 | 追加首个里程碑 |
| 新里程碑规划 | 审视（可选更新） | 追加新里程碑 |
| 执行中新发现 | 不更新，收集到 notes | 不变 |
| 执行结束 | 批量更新 | 标记 done |

### R6: task schema 扩展

现有 task schema 新增字段：
- `space`: 空间坐标 path（如 `sys-cc/proj-cli/mod-cli-init/feat-xxx`）
- `time`: 时间坐标 path（如 `v0.1.4/req-1`）
- `level`: T1-T9 层级标识
- `exec.gates`: 门禁执行结果

### R7: MCP tools 扩展

awf-state 新增 7 个 tools：
- WBS 树管理：`awf_wbs_tree_read` / `awf_wbs_node_update` / `awf_wbs_node_create` / `awf_wbs_node_delete`
- 门禁状态：`awf_gate_status` / `awf_gate_pass` / `awf_gate_fail`

### R8: .awf/ 目录结构重构

新增分布式目录：
```
.awf/
├── versions/    # 版本 state.json 归档
├── issues/      # Issue 跟踪
├── bugs/        # 运行时缺陷
├── reports/     # 测试/审查/lint/汇总报告
├── logs/        # awf run 全量日志
├── wbs.json     # WBS 空间树
└── gates.yaml   # 门禁配置
```
