# awf 任务「只往后放、run 按数组顺序推进」导致前置任务被跳过

- 状态: 待明日定方案（2026-09-08 记录）
- 关联: T1-058（`run.js 改提交/订阅/应答` 需要一个前置 T1-105）、T3-005（依赖 T1-104）
- 类型: awf 产品缺陷（任务创建/调度顺序语义），非本次 v0.2.0 数据问题

## 现象

1. 规划/执行中发现 T1-058 需要先做前置任务，用 `awf_task_create` 新建（T1-105、T1-104）。
2. `awf_task_create` 只能 **append 到任务数组末尾**，没有"插到指定任务前/后"的能力。
3. `awf run` 按**数组顺序**推进（就绪池也是顺序取首），于是新任务排在队尾（idx 133/134），
   它被前面的任务依赖 → 该任务「not ready」被跳过，run 顺着顺序越过无数任务继续往后跑，语义全乱。

本次恰好两处，均为队尾任务被前面任务依赖：

- `T1-058 deps[T1-105]`，而 T1-105 在 idx 134（队尾）
- `T3-005 deps[T1-104]`，而 T1-104 在 idx 133（队尾）

手工重排后已无前向依赖（135 任务），但这是治标。

## 根因

- `awf_task_create` 只 `state.tasks.push`（append），无插入位置参数。
- 运行推进信任任务数组顺序（或就绪池按序取首且不回头），不识别「新任务在依赖者之后」的拓扑倒挂。

## 必改方向（明日确定，选一或多）

1. `awf_task_create` 支持 `insertBefore/insertAfter`（或创建后返回并可 reorder）。
2. run 取下一任务改为**按依赖拓扑**而非数组顺序，append 到队尾不再破坏执行顺序。
3. 就绪池/推进处加**前向依赖检测告警**（任务被后面的任务依赖 → 创建即拦截报错），避免静默跑乱。
