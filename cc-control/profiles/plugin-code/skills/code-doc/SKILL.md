# 文档体系

## 文档分类

### 1. 需求文档（code-doc-base）

- 位置：`docs/features/<需求名>/`
- 内容：目标、边界、场景、验收标准
- 必选，每个需求必须有

### 2. 测试用例（code-doc-test）

- 位置：`docs/features/<需求名>/`
- 内容：基于需求文档的测试场景和用例
- 必选，和需求文档同目录

### 3. 问题中心（code-doc-issues）

- 位置：`docs/issues/`
- 内容：阻塞问题、待决策事项、风险记录
- 状态：开放 / 进行中 / 已关闭

### 4. Bug 记录（code-doc-bugs）

- 位置：`docs/bugs/`
- 内容：缺陷描述、复现步骤、根因分析、修复方案
- 作用：踩坑记忆——同样的错误不犯第二次

### 5. 可复用资源（code-doc-reuse）

- 位置：`docs/reuse/`
- 内容：组件、模块、工具函数、代码片段索引
- 作用：减少重复造轮子

### 6. 决策记忆（code-doc-decision）

- 位置：`docs/discuss/`
- 内容：架构决策、方案对比、技术偏好、踩坑经验
- 格式：背景 → 选项 → 决策 → 理由

## 原则

- 文档与代码同仓库，同提交更新
- 过时文档比没文档更糟——更新或删除
- 增量更新优先于全量重写
- 分类是为了查找快，不是为了分类多
