# 技术选项

## 决策方法

面对多个技术方案时，按以下维度评估：

1. **适配度** — 解决当前问题需要多少额外代码
2. **复杂度** — 引入后整个系统的复杂度上升多少
3. **维护成本** — 团队能否长期维护，依赖是否健康
4. **替代成本** — 将来要换掉的代价有多大
5. **成熟度** — 社区规模、文档质量、生产验证情况

## 决策原则

- 选择最合适的，不是最流行的
- 默认不引入新依赖，除非现有方案确实不够
- 一个依赖解决一类问题，不同时引入功能重叠的库
- 第三方依赖通过适配器层封装，降低替换成本
