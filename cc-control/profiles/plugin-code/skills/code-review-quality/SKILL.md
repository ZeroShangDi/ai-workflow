# 代码质量审查

## 审查维度

1. **正确性** — 逻辑是否正确，边界是否覆盖，错误路径是否处理
2. **可读性** — 命名是否清晰，结构是否直观，意图是否明确
3. **可维护性** — 是否可扩展，是否可测试，是否有重复
4. **一致性** — 是否遵循 code-dev-* 系列定义的规则

## 审查方法

- 逐文件审查，不跳读
- 优先关注核心逻辑路径
- 工具能检查的不靠人眼（格式、类型、lint）

## 输出

- 问题按严重程度：阻塞 / 建议 / 参考
- 每条问题附修复建议
