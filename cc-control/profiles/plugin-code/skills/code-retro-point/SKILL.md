# 项目复盘

## 复盘格式

### Stable（保持）

哪些做法效果好，值得继续保持。

### Improve（改进）

哪些地方可以做得更好。

### Experiment（尝试）

下次想尝试什么新做法。

## 复盘原则

- 每项写具体，不写空话（"沟通需要加强" → "需求变更时应该先更新 issue 再动手写代码"）
- 复盘不是追责，是提炼经验
- 每次复盘最多输出 3+3+3 条
- 复盘记录存入 `docs/discuss/` 保留
