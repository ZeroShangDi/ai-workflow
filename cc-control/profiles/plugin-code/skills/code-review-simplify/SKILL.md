# 代码简化

## 简化目标

在不改变行为的前提下，减少不必要的复杂度。

## 检查项

1. **Rule of Three** — 只出现一两次的模式不要抽象
2. **过度工程化** — 为未来需求写的代码就是债务
3. **死代码** — 未被调用的函数、未使用的变量、注释掉的代码
4. **if-else 链** — 可以用查表法（map）替换
5. **冗余状态** — 能推导的值不要存储
6. **过度配置** — 只有一个值的配置项不需要存在

## 简化原则

- 能删的先删，能合并的再合并
- 简化后行为不变
- 简单的代码不需要注释来解释
