# 高质量代码最佳实践

## 正确性

- 边界条件有处理（空值、极值、并发）
- 错误路径有覆盖（网络失败、超时、权限不足）
- 状态转换有明确的触发条件和目标状态

## 可读性

- 代码自解释：好的命名 > 注释
- 注释只解释"为什么"，不解释"是什么"
- 函数长度：能在一屏内看完
- 嵌套深度：不超过 3 层

## 可维护性

- 一个修改只影响一个地方（DRY）
- 相似代码到第 3 次才抽象（Rule of Three）
- 硬编码值提取为常量或配置
- 魔法数字命名

## 防御性

- 外部数据不信任（API 响应、用户输入）
- 类型系统充分利用（TypeScript 严格模式）
- 断言和类型守卫在边界处
