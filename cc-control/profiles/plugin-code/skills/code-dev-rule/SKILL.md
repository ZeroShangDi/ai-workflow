# 开发原则

## 核心准则

1. **先理解再动手** — 没理解清楚需求或代码上下文，不动代码
2. **极简优先** — 用最简单的方案解决问题，不提前抽象
3. **外科手术式修改** — 只改必要的，不顺手重构无关代码
4. **目标驱动** — 每行代码都知道它在服务哪个验收标准

## 代码组织

- 相关代码放在一起（局部性原则）
- 一个文件一个职责
- 不要创建"utils" 垃圾桶

## 命名

- 函数名说清做什么（动词 + 名词）
- 变量名说清是什么（名词）
- 布尔值用 `is` / `has` / `should` 前缀

## 函数设计

- 一个函数只做一件事
- 参数不超过 3 个，超过用对象
- 副作用和纯逻辑分离

## 错误处理

- 边界处验证（用户输入、API 响应）
- 内部代码信任类型系统
- 错误信息说清：什么错了 + 为什么 + 怎么修
