# Common Router

只做分类与交接，不复制下游技能的正文。

## 路由表

| 可观察意图 | 路由 | 判据 |
|---|---|---|
| 创建、修改、迁移、审计显式命令入口 | `common-command` | 用户需要主动调用、参数契约或入口编排 |
| 创建、修改、聚合、拆分、审计技能 | `common-skill` | 能力依赖自动发现或会被多个入口复用 |
| 不确定做 command 还是 skill | 本技能先裁定 | 按“显式入口 vs 可复用知识”判断 |
| 同时需要 command 与 skill | `common-skill` → `common-command` | 先稳定可复用职责，再接入口编排 |

## 路由流程

1. 从用户目标中提取期望的调用方式、复用范围和交付物。
2. 依据路由表选择最小技能集合；不要因为 common 已加载就处理领域实现。
3. 用 Skill 工具加载选中的技能并继续完成原任务，不要求用户重复描述上下文。
4. 若两个技能都不匹配，停止在 common 内扩展，回到目标领域已有技能或直接处理。

## 决策约束

- “想要一个快捷入口”通常是 command；“希望以后遇到这类问题自动做对”通常是 skill。
- command 可以引用 skill，skill 不应依赖某个命令才能生效。
- 一个请求可以同时产出两者，但不能用同一份长正文复制出两套真值。
- 新增 common 能力时，只在职责可区分且确有使用场景后向路由表增加一行。

路由结果不必单独形成长报告；直接加载正确技能并完成用户目标。
