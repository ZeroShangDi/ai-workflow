# w-doc — 文档管理规范

w-doc 是文档管理的总控：决定「是否生成、生成什么、按什么规则生成」；每类文档的具体写法（模板、命名、时机）由 code-doc 实施。

关联 **awf-task-context**：输入首项能解析为 task ID 时，优先按任务的目标、范围、约束和验收执行；否则进入下述普通输入解析。

## 1. 定位与职责

| 层 | 承载 | 文件 |
|----|------|------|
| 总控 | 生成与否、意图解析、体系框架、质量与路由规则 | 本命令 w-doc |
| 实施 | 每类文档的模板 / 命名 / 创建更新时机 / 删除归档 | code-doc |

## 2. 触发与输入解析

AI 调用时输入不可控，可能是命令、参数或纯文字。先归一化输入，再决定动作：

| 输入形态 | 判定 | 处理 |
|---------|------|------|
| `/w-doc run` | 模块级，目标=模块 run | 功能文档 + 测试用例 |
| `/w-doc run/req-003` | 功能级，目标=功能 req-003 | 三件套（+开发日志） |
| `/w-doc`（无参数） | 无明确目标 | 兜底：从最近 commit / 未过验收的功能定位；定位不到 → 询问 |
| 纯文字「给这次改动写个文档」 | 意图=功能文档 | 从最近 diff 定位模块/功能，走功能级 |
| 纯文字「记录这个 bug / issue / 决策 / 复用点 / 版本」 | 意图=对应类型 | 按「意图 → 类型」映射落对应文档 |
| 带 `--force` | 覆盖 | 忽略增量，全量重写 |

### 意图 → 文档类型

| 场景 | 文档类型 | 落点 |
|------|---------|------|
| 新功能 / 代码变更 | 功能文档 + 测试用例 | `docs/features/` |
| 验收前 | 测试用例 | `docs/features/` |
| 缺陷 | Bug 记录 | `.awf/bugs/` |
| 阻塞 / 待决策 | 问题记录 | `.awf/issues/` |
| 架构决策（人） | 决策记忆 | `docs/discuss/` |
| run 过程决策（AI） | 决策记录 | `.awf/decisions/` |
| 复用点 | 可复用资源 | `docs/reuse/` |
| 版本发布 | 变更记录 CHANGELOG | `docs/CHANGELOG.md` |
| 阶段结束 | 报告 | `.awf/reports/` |

## 3. 文档体系总览

- **级别**：遵循 awf-plan-level，层级 `生态→系统→项目→模块→功能→任务`
- **粒度**：模块级（不含 `/`）| 功能级（含 `/`，= WBS 叶子）
- **位置**：

| 归属 | 类型 → 位置 |
|------|-------------|
| 项目资产 `docs/` | 功能 `docs/features/<name>.md`；测试 `docs/features/<name>.test.md`；开发日志 `.log.md`（同目录）；决策记忆（人）`docs/discuss/`；可复用 `docs/reuse/`；CHANGELOG `docs/CHANGELOG.md` |
| 开发产物 `.awf/` | Bug `.awf/bugs/`；Issue `.awf/issues/`；AI 决策 `.awf/decisions/`；报告 `.awf/reports/`（test/review/perf/lint/summary） |

## 4. 生成规则

- **默认不生成**：文档不是默认产出物，按需生成
- **按需触发**：功能/测试在功能落地或验收前；ADR 在决策时；bug/issue 在发生时；报告随阶段产出
- **读者导向**：每类文档有明确读者和用途（见 code-doc）；无读者不生成
- **消耗可控**：`.awf/config.json` 的 `docs` 段（`enabled` 总开关 + `types`/`reports` 白名单）

## 5. 质量规则

1. **门禁兜底**：产出过 review/test 门禁；schema 或路径不符 → 打回，宁缺勿滥
2. **代码驱动**：描述基于实际代码分析，禁止虚构
3. **增量优先**：增量更新优先于全量重写；过时文档比没文档更糟
4. **术语统一**：遵循 awf-plan-level，禁止混用「需求/功能/模块」
5. **一页一类**：Diátaxis，一页只做一类

## 6. 路由规则

1. 解析输入（含模糊输入）→ 确定粒度 + 类型
2. 目标不存在 → 新建；存在且无 `--force` → 增量；存在且有 `--force` → 覆盖
3. 功能已删除 → 按 code-doc 归档规则处理

> 每类文档的模板、命名、创建/更新时机、删除归档、优化 → **code-doc**
