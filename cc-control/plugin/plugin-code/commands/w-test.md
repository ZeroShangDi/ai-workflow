# w-test

验证指定目标是否满足预期行为，并报告实际证据。按项目已有测试设施和本次风险选择验证方式，不要求每个任务覆盖所有测试层级。

## 确定验证目标

1. 输入含 task ID 时，加载 `awf-task-context`，读取目标、范围、约束和验收条件。
2. 以用户指定范围为准；未指定时选择当前任务改动及其真实影响路径。先检查已有测试、脚本和运行约定。
3. 将验收要求转换为可观察结果，优先验证主行为以及最可能导致错误的边界、状态变化和失败路径。

## 按需设计用例

- 需要从需求推导测试场景、评估用例缺口或输出测试用例清单时，加载 `code-test-case`。
- 仅当用户要求测试文档，或交付明确要求持久化用例/测试报告时，加载 `code-doc`。
- 用例生成和文档化不是每次运行测试的前置步骤；对已有测试直接选择并运行相关验证。

## 执行与判断

- 依据行为选择单元、集成、端到端或其他适合的验证，不为凑层级而重复测试。
- 运行最相关的现有测试；改动跨越契约、配置或多个模块时，按影响扩大验证范围。
- 只有测试覆盖率或其他指标能回答具体风险时才检查，不以指标代替验收。
- 测试优先围绕行为和契约；测试先行适用于能先表达预期行为的开发流程，不是所有测试任务的硬性门槛。
- 失败时区分本次引入、既有失败和环境阻塞；不得删改断言来制造通过结果。

## 报告

简要列出验证范围、实际运行的检查及结果、未验证项和阻塞原因。只有用户或 AWF 流程要求时才生成独立报告文件；不得把未执行的检查写成通过。
