
核心理念
 - 功能分层：命令负责元知识，技能编排与路由，以及其他特定任务中必须要知道或者遵守的规则。技能则负责方法论，领域知识，具体的执行步骤等。技能同级目录增加知识库文件夹，内部包含某个领域具体使用经验。
 - 开发原则：命令是每次任务执行携带的，技能则是每次按需调用，知识库则只在命中固定场景时才使用，它们三层的内容一层比一层多，因此一定要注意消耗优化，越频繁越长驻的内容需要精炼，不是精简而是精炼，信息密度要高，越是较多的内容越是要处理好路由，按需引入，避免阅读大量无关内容。
 - 修改规范：知识库内容可以随意写入，由人工择时统一审核，知识库每个知识一条，互不干扰。命令与技能每次都只做微调，不一次性大改，每次改动都需要人工审批。


临时灵感
 - 重构时才用自底向上的方法能否降低变动频率
 - 技能实现之后需要验证，不被验证的技能不能算做完。
 - 知识库应该围绕问题检索组织
 - 首先就要做两件事，第一，总结穷举这个技能可能面临的问题。第二归纳整理这个问题在历史长河中先辈都用过哪些方法，留下过哪些经验。第三，结合二者，就是知识库的样子。
 - 按我们的项目语境，元知识是对一类问题底层规律的高密度表达。它不只概括经验，还应能：
    - 解释：用少量认知解释多个具体现象。
    - 泛化：在不同实例中仍成立，但边界清楚，不是假装普遍适用。
    - 生成：能从规律推导出新的判断原则、方法和技能。
