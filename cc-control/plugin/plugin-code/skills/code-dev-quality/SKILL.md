# 质量与验证

## 道：质量取舍

- **行为正确是前提**：需求示例只是部分输入。业务约束、状态转换、失败后的状态同样属于正确性；程序能运行、类型通过或正常路径成功不足以证明交付。
- **理解成本决定可读性**：读者应能从命名、控制流和接口理解意图，找到状态与业务规则的归属。文件数、行数、嵌套数是调查线索，不能代替判断。
- **职责决定修改边界**：同一规则有权威位置，不同变化原因保持独立。复用应基于相同语义；扩展应服务已知变化。避免为减少文件数堆成大模块，也避免为“解耦”制造层层转发。
- **质量需要证据**：用行为验证和差异审查支撑结论；验证强度随失败代价和影响范围增长。成本包含返工与维护，不能靠省略必要分析获得表面上的速度。
- **改进服从任务范围**：修复本次引入的问题和完成目标必需的问题。发现无关缺陷时单独报告，不顺带清理；专项知识按真实缺口使用，不全量加载。

## 法：从约束到证据

### 建立判断依据

结合用户目标、现有实现、调用方和既有测试，明确输入、可观察结果、必须保持的约束及允许变化的行为。找出状态所有者、规则所在位置和外部副作用，预测必要修改位置及原因。

对含糊要求提出能区分行为的情境：重复点击算一次还是多次？旧请求晚到能否覆盖新状态？部分成功后重试会不会重复写入？选择与当前任务实际有关的问题；答案无法从契约得出且会改变结果时澄清，不擅自定义业务规则。

### 选择质量关注点

下表覆盖共同质量目标，是按任务选择的判断依据，不要求每次输出完整检查表。

| 目标 | 需要判断的问题 | 可用证据 |
|---|---|---|
| 正确性 | 正常、边界和状态转换是否保持业务约束？ | 验收样例、反例及结果断言 |
| 可读性 | 命名、分支与接口能否直接表达意图？ | 沿一条主要路径阅读，能解释行为而不反复跳转 |
| 可维护性 | 修改原因是否集中，依赖和状态归属是否明确？ | 实际 diff 与影响范围、调用关系 |
| 可复用性 | 共享部分是否具有相同语义和变化原因？ | 调用方契约；复用是否引入调用方特例 |
| 可扩展性 | 已知同类变化能否在明确边界完成？ | 推演一个有依据的变化，检查是否需修改散落分支 |
| 健壮性 | 无效输入、依赖失败和异常顺序是否使状态失控？ | 错误注入、边界和顺序相关用例 |
| 安全性 | 输入、身份、权限及敏感数据边界是否被保护？ | 越权和恶意输入等针对性检查 |
| 高效性 | 是否满足实际资源与性能要求？ | 基线与修改后的测量，避免凭感觉优化 |
| 可测试性 | 能否通过稳定接口验证行为并控制必要依赖？ | 测试是否大量依赖无关内部细节 |
| 可观测性 | 故障发生时能否定位原因和影响，又不泄漏敏感信息？ | 失败时的错误、必要日志或指标 |
| 兼容性 | 既有调用方和持久化数据能否继续工作或迁移？ | 旧输入、旧数据与调用方回归 |
| 可恢复性 | 中断、重试、取消后是否回到合法状态？ | 部分失败、重复执行和恢复路径验证 |
| 可访问性 | 相关界面能否被目标用户感知、理解和操作？ | 键盘、焦点、语义及必要的辅助技术验证 |

### 将风险落实到实现

对本任务最可能或后果严重的失败路径，明确“触发条件 → 错误后果 → 保持约束的设计 → 验证方式”。不以安全检查代替业务正确性，不以框架经验代替职责设计。

若问题在组件/模块职责，使用已有设计能力确定状态与接口边界；若同一规则散落或修改跨越业务边界，使用架构能力判断收敛方式。安全、性能、兼容等专项知识只在对应问题需要时加载，把已确认的约束和证据交给它，避免重复探索。

实现时让命名表达领域含义，减少需要同时记忆的隐藏状态和跨层细节。注释补充代码不能直接表达的业务原因、约束、算法或接口语义。抽取函数、模块或组件必须改善理解、职责或真实复用，不按长度自动拆分。

### 复核并决定是否完成

- 对照约束验证可观察行为，覆盖已识别的重要失败路径；使用已有测试设施，必要时补有区分力的用例。lint、类型检查和构建只证明各自检查范围。
- 沿实际 diff 检查每处变化的必要性、规则是否重复维护、是否扩大公共接口。影响超出预测时重新判断设计；突破用户明确范围或预算时先取得确认。
- 以维护者视角阅读主要路径与错误路径，检查状态、职责及副作用是否可解释，是否存在模糊命名、条件耦合或过度转发。发现问题优先做有针对性的修正。
- 对未满足的验收、未解决的关键风险或无法完成的验证明确说明；不能将未验证写成通过。满足目标与必要质量后结束，不为无依据的“更优雅”继续扩张。

## 术：按需知识库

涉及拆分、复用或指标判断时，读取 [实践参考](knowledge/existing-practices.md) 的相关条目。新增经验可在同级 `knowledge/` 按问题检索，不默认读取整库；没有适用经验时按上述方法推理和验证。

道与法在任务执行中不可自动修改。AI 仅可在已授权的可写技能源知识库中补充或合并经验，记录条件、做法、原因、代价/反例及验证证据；不得写入缓存或构建产物。未经验证的经验标明假设，不能成为强制规则；无可复用新认识时不新增文件。
