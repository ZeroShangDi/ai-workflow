## 有意图地记录日志

- `error`：现在就需要人关注
- `warn`：意外但已处理 — 值得稍后调查
- `info`：关键生命周期事件（会话启动、功能开关、鉴权状态变更）
- `debug`：详细状态，仅本地开发用

每条日志都应回答「诊断问题时有人真的会问」的一个问题。为记而记的日志制造噪音，淹没信号。

## 性能要有基线

关键路径（消息渲染、SSE 处理、API 调用）应有已知的性能画像。改动关键路径代码时考虑：会增加重渲染吗？会阻塞主线程吗？会随时间累积内存吗？

## 生产环境错误监控

生产错误应自动上报 — 不要等用户抱怨。关键错误（鉴权失败、数据丢失、支付问题）应触发告警。不知道它坏了，就无法修复它。
