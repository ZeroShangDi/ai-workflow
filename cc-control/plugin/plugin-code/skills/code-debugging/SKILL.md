# 缺陷调查与修复

## 调查步骤

1. **界定现象**：记录预期与实际行为、触发输入、环境、发生频率和影响范围。优先建立最小且可重复的复现；暂时无法复现时，查找能区分环境、时序和输入差异的证据。
2. **追踪根因**：沿数据流、状态变化、调用链和错误处理定位首次偏离预期的位置。结合相关测试、日志和近期变更检查已有模式，但时间相关性本身不证明因果。
3. **验证假设**：每次提出一个能解释症状的假设，写明它预测什么观察结果，再用最小实验、测试或日志取证。实验应能区分当前假设与合理替代解释；不要靠连续随机修改“试出来”。
4. **修复并回归**：在根因边界修正问题，优先添加能够捕获该缺陷的行为验证，再检查相邻状态和失败路径。验证未能复现或修复没有改变预测结果时，重新检查假设，不扩大补丁掩盖症状。

## 停止与升级

- 根因证据不足时，继续调查或说明阻塞，不把猜测写成结论。
- 同一假设反复被证伪、复现只能靠环境偶发或修复持续跨越多个职责边界时，重新检查问题定义、架构约束和可观测性，必要时向用户说明会改变修复路径的未知条件。
- 交付记录触发条件、根因证据、修复和验证结果；无法覆盖的环境或时序范围要明确标出。
