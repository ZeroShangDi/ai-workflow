# 术语与级别规范

全项目描述用词和层级划分遵循本规范，禁止混用「需求/功能/模块」等近义词。

## 级别定义（决定深度）

```
生态，系统，项目，模块，功能，任务。
```

- 需求定位到层级链上哪一级，就决定树/文档拆到哪一层
- 深度由级别决定；叶子在「模块 ~ 任务」级按任务量浮动（粒度经济）
- 功能 = 默认任务单位；简单可收成模块级任务，复杂向下拆出任务级
- 大多数单仓库项目从「项目」级起步，生态/系统仅多系统集成时用到

## 术语表

| 术语 | 定义 | 对应 |
|------|------|------|
| 模块 module | 功能聚合域（run / init / state / server …） | `docs/features/<module>.md` |
| 功能 feature | 模块内可独立验收的最小逻辑单元 = WBS 一个叶子节点 | `docs/features/<module>/<req-id>.md` |
| 任务 task | awf run 执行单元；通常 1 功能 = 1 任务，复杂功能可拆多任务 | state.json tasks |
| req-id | 功能唯一标识（如 `req-003`） | 功能级文档命名 |
| 需求 requirement | 规划期原始诉求，规范化后即「功能」 | 只出现在规划期，落地统一写「功能」 |
