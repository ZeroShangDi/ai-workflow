# AI 生成测试用例

> 参考：Lee Copeland《A Practitioner's Guide to Software Test Design》— 系统性测试设计技术

## 生成方法

基于需求文档和代码实现，先用设计技术确定"测什么"，再落成用例。顺序：

1. 读需求 → 找出所有输入、规则、状态、边界
2. 按场景选设计技术（下表）
3. 生成用例 → 按 覆盖维度 校验是否有缺口
4. 输出标准结构

## 测试设计技术（按场景选）

| 场景 | 技术 | 说明 |
|------|------|------|
| 数值范围输入 | 边界值分析 + 等价类划分 | 覆盖最小/最大边界及两侧 |
| 多条件业务规则 | 决策表 | 规则条件组合 → 对应行为 |
| 有状态的工作流 | 状态转换测试 | 合法/非法状态迁移 |
| 参数组合爆炸 | 成对测试（pairwise） | 每对参数值至少出现一次 |

### 边界值分析（BVA）

缺陷集中在边界，测边界两侧：

- 年龄字段合法范围 18-120 → 测：17（非法）、18（下界）、19、119、120（上界）、121（非法）

### 等价类划分（EP）

每个等价类测一个代表值，避免逐值穷举：

- 折扣规则（1-10 无折扣 / 11-100 打 9 折 / 101+ 打 8 折）→ 测 5、50、200 三个代表，覆盖全部行为

### 状态转换测试

- 状态机：Logged Out → Logged In → Premium
- 合法转换：Login、Upgrade、Logout
- **非法转换必测**：Logged Out → Premium（应拒绝）；Suspended → Premium（应拒绝）

### 成对测试（pairwise）

- 3 参数 × 3 取值全组合 27 个 → pairwise 压到 9-12 个，仍覆盖每对取值组合

## 测试用例结构

```
用例 ID: TC-<序号>
场景：<简要描述>
前置条件：<测试前需要什么状态>
操作步骤：<执行什么操作>
预期结果：<应该看到什么>
优先级：P0(核心) / P1(重要) / P2(次要)
```

行为描述用 Given-When-Then 风格，让失败信息直读：

```
Given 用户已登录且商品有库存
When  用户提交订单
Then  订单创建成功，返回订单号
```

## 覆盖维度（生成后逐项自查）

- [ ] 正常路径 — 主流程能走通
- [ ] 边界 — 空值、极限值、边界两侧
- [ ] 异常 — 网络失败、超时、权限不足、依赖返回错误
- [ ] 状态转换 — 合法与非法迁移
- [ ] 并发 — 重复提交、竞争条件（关键场景）
- [ ] 安全 — 未授权访问、注入输入（含用户输入的接口）

## 原则

- 测试行为，不测试实现——重构后测试不改，测试设计才正确
- 一个测试一个场景，不塞多个断言混合
- 测试名描述场景和预期结果：`"当用户未登录时，提交订单返回 401"`
- 用例数量求"覆盖充分"不求"多"——等价类合并重复，pairwise 压组合
- 每条用例标注对应的验收标准（如有），可追溯
