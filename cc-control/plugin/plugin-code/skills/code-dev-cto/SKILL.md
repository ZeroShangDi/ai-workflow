# 技术选型

以适配当前约束的成熟方案降低总成本；自研也是候选方案之一。

## 判断原则

- **先看硬约束**：核心能力、运行环境、兼容范围、数据边界、许可和部署要求决定方案是否可用；偏好与流行度不能替代适配性。
- **比较总成本**：考虑接入、定制、学习、测试、安全、运维、升级和退出成本，不只比较采购或开发成本。
- **证据与风险相称**：核实会影响结论的事实；只验证可能推翻推荐的关键未知点。
- **控制选型范围**：从项目已有能力开始，逐步查看技术栈和外部方案；找到满足约束的可行路径后停止，不为凑候选而穷举。

## 执行流程

1. 从需求、仓库、依赖和已有决策中提取约束；已有选择仍适用时直接沿用。
2. 找出少量可行方案，核实其关键能力、维护状态、版本适配、许可和安全信息。当前外部信息未核实前，不把记忆当作事实。
3. 排除不满足硬约束的方案，比较适配程度、完整成本、主要风险与可逆性；同时评估最小自研方案。
4. 对可能改变推荐的未知点做最小验证。验证受限时标明未验证内容及影响。
5. 交接推荐方案、成立条件、实施边界、主要代价和未验证项，供设计与实现继续使用。

硬约束已满足、关键未知点已验证或明确受限，且剩余差异不影响决定时停止。只有需求、约束或证据变化时才重新选型。

选型建议不扩大任务授权。替换现有技术栈、迁移数据、引入付费或外部服务、扩大目标前，先取得用户确认。

## 按需经验

当选型结论可能受已有经验影响时，根据任务关键词检索同级 `knowledge/`，只读匹配条目；无匹配时按本技能的方法判断，不读取整库。
