# 空间任务树生成

## 解释：这套东西是干嘛的

接收一个需求，生成 wbs 格式的空间任务树。树的五要素各管一件事：

| 要素 | 回答的问题 | 机制 |
|------|-----------|------|
| **级别** | 树拆多深？ | 空间层级定位，决定深度 |
| **拆分规则** | 每个节点下几个子节点？ | 子交付物分解，决定广度 |
| **共享节点** | 公共逻辑放哪？ | 节点上提/下沉，提炼公共模块，增强可维护性 |
| **拆分步骤** | 怎么构建树？ | 一次拆一个节点、只拆一层 |
| **变更传播** | 树生成后怎么改？ | stale 标记 + 差分重拆 |

## 级别定义（决定深度）

级别与术语遵循 **awf-plan-level**（权威）：`生态，系统，项目，模块，功能，任务。`

## 拆分规则（决定广度）

1. **子交付物分解**：可以独立验证的子交付物数量 = 子节点数量
2. **共享上提**：同一段逻辑被不同地方使用 → 上提为共享服务节点；每个节点独有的部分留在原节点
3. **上提层级由适配范围决定**：只适配当前模块 → 提到模块内；适配多个模块 → 提到项目级；依次类推
4. **共享节点职责边界**：只写对内的实现逻辑 + 对外暴露的接口定义；不写业务方调用时的具体逻辑。业务调用的具体逻辑在对应模块/按钮任务下定义

## 拆分步骤（怎么构建树）

1. **定级**：定义当前节点级别，如果已经到达任务级别，则停止向下拆分
2. **估量**：定义任务工作量，如果任务量过大，需要拆分
3. **定依赖**：定义任务依赖关系
4. **下拆**：根据当前级别向下拆分，每次只拆分一个节点，只向下拆分一层

## 变更传播（更新树）

树生成后需要改动时：

1. **范围/上层变更** → 受影响子树标 `stale`
2. **只重拆受影响子树**，差分更新，不全量重拆
3. **每层/分支落盘 checkpoint**（`.awf/plan/wbs/<node-id>.md`），可中断可恢复
4. 跨模块边界变更先动契约（接口定义），返工隔离在子树内

## 原则

1. 默认拆分到"任务"级别，但当任务量小时也可以停止向下拆分
2. 被依赖的任务需要优先拆分，或者先定义契约，原则上尽量减少阻塞
3. 任务拆分时遵循"模块"及以上广度优先，"功能"及以下深度优先拆分原则
4. 当任务量过大上下文不足以完成所有拆分时要及时落盘，保存至 `.awf/plan/wbs/<node-id>.md`

## 示例

```
图片hover（模块）
  - 对话（共享 · 模块级：只适配图片hover）
    - 图片通用的调起对话方法
  - 缓存（共享 · 模块级）
    - 图片上传内存缓存逻辑，最大50张，防止图片重复上传
  - 意图识别按钮
    - 云控配置（本按钮特有项：场景云控比例；总比例/黑名单属项目级云控）
    - 按钮完整链路
      - UI，胶囊以及动画状态
      - 意图识别分析接口调用
      - 显示逻辑判断，处理云控，设置页等配置决定是否生效
      - 按钮点击后完整交互逻辑，包括，上传，存入缓存，识别，返回结果回填，点击调起对话（调用共享能力，不重复实现）
      - 异常处理，包含触发风控，接口失败，缓存失败，识别失败等
    - 打点（本按钮打点要求；打点体系封装在项目级）
  - 识图提问按钮（类似上）
  - 快速提问按钮（类似上）
  - 关闭
    - 设置页，开关，产品图，黑名单（引用项目级设置中心）
    - 关闭组件，调用并增加关闭icon到图片hover（图片识图专属）

（项目级：云控、设置中心、打点体系 —— 适配整个插件，独立模块）
```

### 示例解读

- **模块级共享**：对话、缓存只被图片hover内按钮使用 → 上提到图片hover模块下，不放到项目级
- **项目级共享**：云控、设置、打点适配整个插件 → 上提到项目级，示例范围外不展开
- **按钮内**：云控配置只留"场景云控比例"这类按钮特有项；上传/缓存/对话在链路里以"调用"方式出现，不重复实现
- **任务描述**：业务语言（"最大50张，防止图片重复上传"），可直接验收

## WBS 节点结构

```json
{
  "id": "W2-001",
  "title": "节点名称",
  "level": 2,
  "parent": "W1-001",
  "children": ["W3-001", "W3-002"],
  "description": "这个节点要交付什么",
  "acceptance": "怎样算完成"
}
```

id 遵循编号规范 `{前缀}{级别}-{序号}`（见 w-plan 的编号规范章节）：`W`=WBS 节点，级别=树深度，序号=同级内 3 位补零递增。
