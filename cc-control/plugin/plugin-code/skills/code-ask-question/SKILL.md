# 提问规范

遇到阻塞性问题时，先整理再提问。一个问题描述不清楚，回答也不会清楚。

## 一句话问题公式

```
当我 <做某事> 时，我期望 <结果>，但实际 <发生了什么>。
```

- "当我上传 500KB 以上图片时，我期望服务端接受，但实际返回 413。"

把问题收敛成一句话，本身就是排查过程——说不清楚一句话说明还没理解问题。

## 提问模板

```
1. 背景：我在做什么（目标）
2. 现状：遇到了什么问题（具体现象、报错信息）
3. 尝试：试过什么方法、为什么没继续
4. 阻塞点：具体卡在哪里
5. 期望：想要什么结果
```

## 防 XY 问题

**XY 问题**：问的是自己猜的解法（X），而不是真正要解决的问题（Y）。

- ❌ "怎么用正则从 XML 里取值？"（X）→ 正则解析 XML 是错误方案
- ✅ "我在解析一段 XML，需要取出 <name> 的值，最好的方式是什么？"（Y）

提问前自问：**我描述的是真正的问题，还是我猜的方案？** 说出最终目标和成功标准，不预设方案——帮手可能给出更干净的路。

## 尝试过的要写全

- 写清已试方法 + 结果 + 为什么放弃，让别人能接续你的排查，而不是从头再来
- "已确认 Nginx client_max_body_size 是 20M，怀疑是网关层限制" —— 排除了一个分支，直接锁定剩余可能

## 反例

"这个报错了怎么办？" → 缺背景、缺报错信息、缺尝试历史、可能是 XY 问题

## 正例

"我在实现图片上传功能，上传 500KB 以上的图片时服务端返回 413。已确认 Nginx 的 client_max_body_size 已经是 20M，怀疑是网关层的限制。现在需要确认网关配置在哪里改。期望是让大图也能上传成功。"

## 自检清单

- [ ] 一句话能说清"期望 vs 实际"吗？
- [ ] 描述的是目标（Y）而不是方案（X）吗？
- [ ] 报错信息全文贴上了吗？
- [ ] 已尝试的和为什么失败写了吗？
- [ ] 需要的最小复现场景给出来了吗？
