# 安全差异审查

从受保护资产和信任边界出发检查本次差异，不按文件名机械套完整漏洞清单。具体防护方法由 `code-security` 承载；需要核实控制设计或修复细节时，只读取匹配的问题与经验。

## 检查方法

1. 找出本次改动涉及的资产、主体、入口、信任边界和敏感操作；沿不可信输入追踪到数据库、命令执行、HTML/URL、文件系统、外部网络或受保护资源等实际接收点。
2. 对相关入口推演可验证的滥用路径：攻击者控制什么、能否绕过校验或授权、会影响哪些数据或操作。检查服务端决策、资源归属、失败分支和日志/错误信息时，只覆盖与差异有关的边界。
3. 区分身份认证、对象/动作授权、输入校验、输出编码和 CORS 等不同控制；某一层存在不代表其他层已满足。不可猜测的 ID、隐藏按钮、前端校验或宽窄不一的 CORS 本身不能证明授权成立。
4. 报告时指出触发条件、可达代码路径、实际影响和证据位置。明确哪些已由代码或测试确认，哪些仍依赖环境或调用方信息；不要把可能性写成已复现漏洞，也不要因缺少动态复现就隐藏有充分证据的风险。
5. 审查新增依赖或第三方调用时，核对本次真实引入的来源、权限和执行面；只有相关风险成立时才要求专项供应链检查。

不要默认运行主动攻击或触碰外部系统；审查限于用户授权范围内可验证的代码与环境。报告严重程度、位置和修复建议遵循 `w-review`，本技能不另设平行报告格式。
