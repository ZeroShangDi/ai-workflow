# 需求规范化

将模糊的、口语化的需求转为结构化描述，确保后续 WBS 和任务拆分在同一基线上进行。

## 核心定义

输入归一化：无论用户以什么形式描述需求（一句话、一段话、列表），统一转为结构化格式。

## 规范化结构

每个需求必须包含以下四要素：

### 1. 目标

- 一句话说清要达成什么
- 不描述实现，只描述结果

### 2. 边界

- 明确做什么（in scope）
- 明确不做什么（out of scope）

### 3. 场景

- 谁在什么情况下使用
- 主要路径和异常路径

### 4. 验收标准

- 可验证的完成条件（是/否可判断）
- 至少 3 条

## 规范化流程

1. 提取核心目标
2. 划清边界（宁可少做，不超范围）
3. 梳理用户场景（正常 + 异常）
4. 定义验收标准（可验证、可量化）
5. 与用户确认（边界和验收是否存在分歧）

## 示例

```
原始需求："加个搜索功能"

规范化后：

目标：用户能通过关键词搜索文章标题和内容

边界：
  in — 标题搜索、内容搜索、关键词高亮
  out — 全文索引、拼音搜索、搜索建议、搜索历史

场景：
  1. 用户输入关键词，回车或点击搜索按钮
  2. 无结果时显示空状态提示
  3. 输入为空时按钮置灰
  4. 搜索失败时显示错误提示（不白屏）

验收标准：
  1. 输入关键词 → 显示匹配结果
  2. 无匹配 → 显示"未找到相关结果"
  3. 结果中的关键词高亮显示
  4. 请求超时 5s → 提示"搜索超时，请重试"
```
