# 代码质量目标

本插件中的开发命令与技能以以下目标指导设计、实现和验证。目标适用于最终代码产物，不能以加载技能的数量、修改文件数量或检查流程长度代替质量判断。

| 目标 | 要求 | 判断依据 |
|---|---|---|
| 正确性 | 实现业务语义，满足约束和不变量；正常、边界、异常及并发情况下行为成立。 | 验收覆盖真实行为，关键状态转换与失败路径有验证证据。 |
| 可读性 | 命名表达意图，控制流清晰，代码组织便于局部理解，注释解释必要的原因和约束。 | 维护者能定位行为并理解其原因，无需在大量文件间跳转或推测隐含规则。 |
| 可维护性 | 职责明确，业务决策有权威位置，依赖关系清楚，修改影响可预测。 | 一次需求变更只影响必要位置，能够定位问题并验证修改，不夹带无关清理。 |
| 可复用性 | 对具有相同语义和变化原因的能力进行复用，接口清楚，避免重复维护同一规则。 | 复用减少重复且不绑定无关功能；不为单次使用强行提取通用模块。 |
| 可扩展性 | 为已知或有证据的变化提供明确扩展位置，保持职责和依赖边界稳定。 | 增加一种合理的同类行为时，修改集中在对应边界，不需遍历散落分支；不为假想需求搭建框架。 |
| 健壮性 | 面对无效输入、资源限制、依赖失败和意外调用顺序时，行为可控，状态一致。 | 检查与任务有关的空值、重复操作、异步乱序、取消、卸载及异常路径，不静默吞错。 |
| 安全性 | 在输入、身份、权限、敏感数据和外部执行边界实施必要保护。 | 服务端授权、输入处理和数据保护有针对性验证；不以隐藏入口或难猜的标识符代替授权。 |
| 高效性 | 在实际资源与性能目标下，合理使用计算、内存、网络、存储及构建资源。 | 用测量和目标判断瓶颈，验证优化收益；没有证据时优先清晰、正确的实现。 |
| 可测试性 | 核心行为可独立验证，依赖和副作用可控制，测试保护稳定契约。 | 无需大量模拟内部细节即可验证行为，失败能定位问题，测试不锁死内部组织。 |
| 可观测性 | 提供足够且适度的错误、日志及必要指标，使故障能够被发现和定位。 | 能知道发生了什么、影响范围及失败原因；避免敏感信息泄漏和无效日志堆积。 |
| 兼容性 | 明确接口、数据格式和已有调用方式的兼容边界，变化时提供必要的迁移或废弃策略。 | 已支持行为不会无意失效；破坏性变化被明确识别，并验证受影响的调用方。 |
| 可恢复性 | 失败或中断后能够按业务要求重试、取消、回滚或恢复到一致状态。 | 重试不会重复产生不应重复的副作用，部分完成状态有明确处理方式，恢复路径可验证。 |
| 可访问性 | 涉及界面时，让目标用户能够感知、理解和操作功能。 | 根据场景验证键盘操作、焦点、语义、读屏支持及错误反馈。 |

## 应用原则

- 正确性、清晰职责、可读性和必要的行为验证是开发基线；专项要求按任务风险和实际场景提高。
- 各目标需要共同权衡，不要求每项达到最大化。复用和扩展不能以增加无必要的抽象、耦合或理解成本为代价。
- 速度、质量与成本共同约束执行方式。先满足验收和必要质量，再减少无效探索、重复上下文与过度流程；成本包含返工、缺陷及后续维护。
- 每项适用目标应落实为具体设计判断和验证证据。格式校验、lint 或构建成功不能单独证明代码达到上述目标。

## 技能组织

命令 `w-*` 承载活动流程、输出要求和路由；`code-*` 承载可跨活动复用的领域方法；只有存在独立方法时才保留活动专项技能（如 `code-debugging`、`code-review-security`、`code-test-case`）。技能按需加载，知识库仅在命中具体问题时读取。

知识库的统一条目结构为：问题标题、1–4 个关键词、答案。答案可使用步骤、列表、表格或流程；不同问题分别成条，不用主题大杂烩代替可检索经验。`code-dev-rule/knowledge/` 与 `references/` 下还保留未纳入路由的旧材料，不能当作当前规则；清理前由人工审阅。

### 规划技能

`awf-plan-level`、`awf-plan-norm`、`awf-plan-wbs`、`awf-plan-tasks`、`awf-plan-prompt`：分别负责规划术语、需求规范化、WBS、任务清单和执行提示词。

### 通用工作技能

`code-context-onboard`、`code-ask-question`、`code-commit-gitflow`、`code-doc`、`code-retro-point`：负责上下文交接、问题表达、提交流程、文档和复盘。

### 领域技能

| 技能 | 职责 |
|---|---|
| `code-tech-selection` | 技术选型 |
| `code-design` | 架构与模块设计 |
| `code-compatibility` | 兼容与迁移 |
| `code-quality` | 质量与验证 |
| `code-performance` | 性能 |
| `code-security` | 安全 |
| `code-vue` / `code-react` | 框架实践 |

### 活动专项技能

| 技能 | 路由信号 |
|---|---|
| `code-debugging` | 使用 `/w-debug` 定位并修复缺陷 |
| `code-review-security` | 审查涉及安全边界 |
| `code-review-performance` | 审查涉及性能目标或热点 |
| `code-review-architecture` | 审查涉及结构边界或架构约束 |
| `code-test-case` | 需要生成或评估测试场景 |

`code-dev-rule` 目前仅保留迁移提示和待人工审阅的旧知识文件，不属于有效路由；旧知识完成审阅后再清理。部分 `references/` 文件同样是未路由历史材料。其余 AWF 运行态能力由各自插件管理，不列入本目录清单。
