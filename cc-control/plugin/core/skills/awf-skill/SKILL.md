# Skill 管理

管理 skills/ 下所有 skill 的完整生命周期。按道法术器四层组织。

---

## 道 — 心法

核心原则，判断 skill 好不好的标准。

- 好技能 = 专家知识 − Claude 已知。删除测试：删掉这句，任务还能不能完成？能，就删。
- 教怎么想，不教怎么做。步骤会过时，判断力不会。

---

## 法 — 方法论与规则

### 创建方法论（TDD）

先看 agent 没 skill 时怎么失败（RED，记下失败原话和借口）→ 写最小 skill 只针对那些失败（GREEN）→ 堵新漏洞（REFACTOR）。

没有失败的测试，就没有 skill。

### 命名规则

```
{前缀}[-{分组}]-{主题}

前缀:  awf    工作流引擎（plan/run 阶段 + 通用 state/skill）
       code   编程实践（dev/review/测试/文档/git）

分组:  可选，同前缀下按功能细分：
       awf   → run（运行态）/ plan（规划态）
       code  → dev（开发）/ review（审查）
       无分组 = 通用（如 awf-state、code-doc）

主题:  kebab-case，一个英文词或词组，不用缩写
```

| 检查项 | 规则 |
|--------|------|
| 前缀 | 必须是 awf / code 之一 |
| 分组 | 有则用约定分组（run/plan/dev/review），无则省略 |
| 主题 | kebab-case，一个英文词或词组，不用缩写 |
| 唯一性 | 同前缀同分组下主题唯一 |

### 体积规则

| 规则 | 限制 |
|------|------|
| 单文件上限 | SKILL.md ≤ 300 行 |
| 超出时 | 拆分 → 精简 → 外迁（按此顺序处理） |

### 边界规则

- 两个 skill 不能说同一件事
- 同前缀同分组已有 skill，必须合并到已有 skill
- 不确定是否重叠时，先对比 description 和主题

### 生命周期

| 状态 | 条件 | 操作 |
|------|------|------|
| 活跃 | 近期被触发 | 保持 |
| 待清理 | 连续多月未触发 | 确认后删除 |
| 已废弃 | 功能已被覆盖 | 删除 |

## 术 — 写法技巧

### description 写法

第三人称「Use when…」+ 触发症状 + 排除条件 + 关键词（错误信息/症状/同义词/工具名）。

别写流程步骤——写了怎么做，agent 拿它当捷径、跳过正文。

### 形式匹配失败类型

| 失败类型 | 正确形式 | 错误形式 |
|---------|---------|---------|
| 知道规则但压力下违规 | 禁止 + 借口对照表 + 红旗 | 软指导（"建议""考虑"） |
| 输出形状不对 | 配方（写清输出的部分与顺序） | 禁止式（"别复述"） |
| 漏掉必填项 | 结构性（模板里的 REQUIRED 槽位） | 附近写散文提醒 |
| 行为看条件 | 条件式（基于可观测谓词） | 无条件规则 + 豁免条款 |

### 防理性化

给易被钻空子的规则配「借口对照表」（每句借口 → 现实）+ 红旗清单，让 agent 能自查。

### token 精简

深细节外迁 references/、可复用代码进 scripts/、交叉引用而非重复、一处好例子胜过多处平庸例子。

## 器 — 载体与测试

### 文件结构

```
skills/{name}/
└── SKILL.md          # 唯一文件，中文编写
    （体积超限时外迁：references/ 重参考、scripts/ 可执行工具）
```

### SKILL.md 模板

```markdown
---
name: {前缀}[-{分组}]-{主题}
description: >
  [一句话说明这个 skill 做什么]
  [触发条件：什么时候自动加载]
---

# [标题]

[内容：心法（一句话核心原则）→ 具体规则/流程 → 示例 → 边界和注意事项]
```

### 测试装置

压力场景 + 子代理：RED 用无 skill 的 agent 记失败原话，GREEN 验证合规，micro-test 5+ reps 对比无指导对照组。
