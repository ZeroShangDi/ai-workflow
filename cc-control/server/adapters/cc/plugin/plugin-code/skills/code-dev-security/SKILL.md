# 防御性编程与安全实践

## 防御原则

1. **不信任外部输入** — 用户输入、API 响应、第三方数据一律不可信
2. **最小权限原则** — 只给完成任务所需的最小权限，默认拒绝
3. **纵深防御** — 单点防护不够，多层防线（输入校验 + 输出编码 + 服务端鉴权）
4. **默认安全** — 安全选项默认开启，关闭需显式决策
5. **失败关闭（fail closed）** — 出错时拒绝访问，不降级为放行

## 常见漏洞与防御

### 注入类

| 漏洞 | 场景 | 防御 |
|------|------|------|
| SQL/NoSQL 注入 | 拼接查询串 | 参数化查询/prepared statement，禁止字符串拼接 |
| 命令注入 | 用户输入拼进 shell | 不用 `exec()` 拼字符串，用参数数组 |
| XSS | 用户内容渲染进 HTML | 默认 `.textContent`；必须 `innerHTML` 时先 DOMPurify；禁 `eval`/`new Function` |
| 路径穿越 | 用户文件名拼接路径 | `path.resolve()` + 前缀白名单校验 |

### 访问控制

- **服务端鉴权每个请求** — 不信任前端隐藏字段或客户端状态：`if (order.userId !== user.id) return 403`
- **IDOR** — 用 UUID 不用自增 ID；访问他人资源要校验归属
- **CORS** — `*` 只用于公开只读数据；认证接口用白名单
- **SSRF** — 用户提供的 URL 不可信，host/port/path 白名单
- **CSRF** — 状态变更请求带 CSRF token / SameSite 校验

### 认证与会话

- 密码用 bcrypt/Argon2id，绝不用 MD5/SHA-1
- 会话 token 加密随机（≥128 bit），cookie 设 `HttpOnly` + `Secure` + `SameSite`
- 登录后轮换 session id（防固定攻击）
- 登录失败限速 + 锁定（如 5 次失败锁 15 分钟）

### 敏感数据处理

- 密钥/token 永不硬编码：环境变量或 secrets 管理（Vault/云 KMS）
- 日志永不打印：密码、token、身份证号、支付信息
- 传输全程 HTTPS（TLS 1.2+）；敏感数据静态加密（AES-256-GCM）
- 错误信息不暴露堆栈给用户，服务端记录、客户端给通用提示

### 依赖安全

- 定期 `npm audit` / Dependabot，高危漏洞及时升级
- 精确版本锁定 + `npm ci` 可复现构建
- 供应链风险：慎用安装期执行脚本的包；三方脚本加 SRI
