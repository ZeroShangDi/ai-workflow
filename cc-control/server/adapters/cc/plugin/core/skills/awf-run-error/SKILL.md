# 运行时异常处理

执行偏离预期时，先归类，再决定自愈还是升级。不要盲目重试。

## 异常类型与识别

| 类型 | 表现 | 识别方式 |
|------|------|---------|
| 超时 | 任务长时间无 done、Stop hook 未触发 | 编排器超时判定 |
| 报错 | 命令/测试/构建非零退出 | awf_capture_pane 看报错输出 |
| 卡死 | 无输出、无状态推进、重复相同动作 | 多轮追问无进展 |
| 偏离 | 产出与 acceptance 不符、改了无关文件 | 对照 exec.files + acceptance |

## 恢复策略

| 类型 | 动作 |
|------|------|
| 超时 | 先查是否其实已完成（exec.result 非空）；否则重试，连续超时由编排器标 blocked |
| 报错 | 定位根因 → 修复 → 重跑（衔接 w-debug） |
| 卡死 | 多轮追问无果 → 标 blocked，升级人工 |
| 偏离 | 回撤本次改动 → 重开（衔接 awf-run-reset） |

## 自动恢复 vs 人工介入

- **自动恢复**：错误可定位、修复路径清晰、无需外部输入
- **人工介入**：需外部决策/信息、技术阻塞、同一问题反复失败 → 建 Issue 升级

Issue 升级格式见 `references/issue-escalation.md`。

## 原则

- 先归类再动手，不盲目重试
- 自愈失败两次就该升级，不无限循环
