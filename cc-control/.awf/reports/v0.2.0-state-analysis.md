### 2.2 停止的证据链

1. `state.lastUpdated` = `20:28:01.355Z`，**恰好等于 `T3-011` 的 `startedAt`** —— 派发该任务后再无任何状态写入。
2. 此刻新起过一个 run 日志目录 `0.2.0-2026-09-10T20-26-43/`，**只有 5 行头**（`started: 2026-09-10T20:26:43.746Z`，无任何提示词）。
3. `T1-112` 新建的 server 日志 `.awf/logs/server.log`（mtime 04:28）给出了决定性一行：

```
cc-control listening on http://127.0.0.1:8787
  (session 'cc-pe22fe94169be-pe22fe94169be') pid=59631
  project=.../cc-control at 2026-09-10T20:26:43.749Z
```

4. 之后 **207 行** `can't find session: cc-pe22fe94169be-pe22fe94169be` —— 宿主的 tmux 操作全部落空。
5. tmux server 整体消失（`no server running on /private/tmp/tmux-501/default`）—— 与「运行会话被 `doCleanup` 杀掉、无其他会话」一致。

### 2.3 根因：`CC_SESSION` 泄漏 → 会话名双重后缀

**机制**（可复核）：

| 环节 | 位置 | 行为 |
|---|---|---|
| bootstrap 注入 | `src/cli/run.js:256` | `CC_SESSION: sessionName`，而 `sessionName` 已是**项目级**会话名 `cc-<projectSid>` |
| 起 server 时不洗环境 | `src/cli/run.js:218` | `env: { ...process.env, CC_PORT, CC_PROJECT }` —— **没有剔除 `CC_SESSION`** |
| 读会话名 | `src/lib/runtime-config.cjs:49` | `getSessionName(env)` → `readRuntimeConfig(env).session`（吃 `CC_SESSION`） |
| 再拼一次 sid | `src/lib/run-context.cjs:45` | `runSessionName = sid == null ? session : \`${session}-${sid}\`` |

于是：`session='cc-pe22fe94169be'` + `sid='pe22fe94169be'` → **`cc-pe22fe94169be-pe22fe94169be`**。

**触发条件**：**从 run 会话内部**启动 server（或任何构建 run-context 的进程）。本次即「老 server 已不在 → 某个从会话内发起的 `awf run` 走到 `ensureServer` → 新 server 继承了 `CC_SESSION`」。

**归属**：与 `.awf/issues/001`（plan/run 内嵌 cc 与普通 cc 的隔离）**同族** —— 都是**运行态身份经环境变量泄漏给子进程**。`CC_SESSION` 与 `CC_SID`/`CC_PROJECT` 是同一层「身份」，前者的治理从未被纳入 W3-006。

## 四、结论与建议

### 4.1 本次检查的判定

- ✅ **代码变动无错误处理** —— 门禁三绿 + 构建打包实测通过，已提交 `8c6d88b`。

- ❌ **run 未完成且已停止** —— 停在 `T3-011`，残留 `mode=run` 与 `active` 状态。

### 4.2 建议

1. **新缺陷立任务**：`CC_SESSION` 泄漏导致的会话名双重后缀。修法两条（可合并）：
   - `ensureServer` 起 server 时**洗掉 `CC_SESSION`**（与 harness 的 `sanitizedEnv` 同口径）；
   - `run-context` 对「session 已含 sid 后缀」做幂等保护（双重后缀应显式报错而非静默生成）。
   建议并入 `T1-113`（D 的 sid 治理），因为它与 `CC_SID` 注入端是**同一层身份的同一个洞**。
2. **处置残留状态**（`mode=run` / `T3-011 active`）后再决定是否 `--resume`。
3. **`check:arch` 补一条不变量**：会话名不得出现重复后缀（可作为 `T1-114` 已留的「可配置结构断言」的第一个用例）。
