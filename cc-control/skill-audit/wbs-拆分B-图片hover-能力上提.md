# 拆分B — 图片hover 能力上提版

> 我此前的拆分：把共享能力（云控/打点/上传/设置）上提到项目级，与图片识图平级。
> 结构特征：项目 → 模块（远程配置/打点/上传/消息路由/设置中心/图片识图）→ 功能 → 任务。

## 项目级（上提的共享模块）

```
AI 助手插件
├── 远程配置（云控）
│   ├── 配置拉取与缓存
│   ├── 配置结构定义
│   └── 配置读取接口
├── 打点体系
│   ├── 展示打点
│   ├── 点击打点
│   └── 请求打点
├── 上传服务
│   ├── 直传上传
│   ├── 云存储上传
│   ├── 意图识别轮询
│   └── 内容风控处理
├── 消息路由（后台）
│   ├── 消息分发
│   └── 侧边栏通道
└── 设置中心
    ├── 设置页框架
    ├── 模块开关设置
    └── 域名黑名单
```

## 图片识图模块

```
图片识图（模块）
├── 识图消息协议
├── 悬停触发链路
├── 传统提问模式
├── 快速提问模式
├── 场景识别模式
└── 识图缓存
```

## 结构解读

- **聚合轴 = 能力**：共享能力全部上提到项目级，只写自身实现。
- **图片识图内部**只剩真正专属的东西（协议 / 触发 / 三模式 / 缓存），通过 deps 引用共享模块。
- **任务描述工程化**：写"实现某能力 + 完成到什么程度"，较抽象。
